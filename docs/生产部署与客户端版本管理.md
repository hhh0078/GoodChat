## 容器与代理

仅新建GoodChat应用容器，复用 `good-headhunter-data-services` 网络中的现有 `postgres`、`redis`。PostgreSQL使用独立的 `goodchat_saas` 数据库与应用账号；Redis使用数据库6，并为心跳键使用GoodChat前缀。不会创建新的PostgreSQL或Redis容器。

正式应用容器名为 `goodchat`，仅绑定宿主机回环地址：13100提供官网、API、WebSocket；18181提供隔离渲染服务，官网网关按固定静态路径转发。Nginx使用现有宝塔站点与证书，将请求转发到13100，支持WebSocket升级，并直接提供 `/clients/` 下的安装包和断点下载。

当前应用镜像同时包含Go API、Next.js和本地可信网关。应用以非root身份运行，数据库运行账号没有超级用户或绕过RLS权限。独立迁移账号只用于迁移和首次初始化。

## 每分钟自动部署

宝塔任务“GoodChat主分支自动部署”每分钟执行：

```sh
GIT_TERMINAL_PROMPT=0 /usr/bin/python3 /www/wwwroot/goodchat.58it.cn/app/deploy/auto-deploy.py >> /www/wwwroot/goodchat.58it.cn/private/deploy.log 2>&1
```

部署脚本以文件锁防止重叠，拉取 `main` 并仅快进，不覆盖服务器未提交修改。提交未变化时不重复构建；仅文档或桌面客户端代码变化时跳过服务镜像构建。服务代码有变化时构建镜像、执行数据库迁移，先用候选容器检查依赖健康，再切换正式容器。启动失败时恢复旧应用容器；数据库迁移不会逆向回滚，因此迁移需要保持向后兼容。

**按用户要求，自动部署不进行数据库备份，也不进行目录备份。** 旧应用容器只用于启动失败时恢复，不复制数据库、上传数据或目录。脚本只回收带GoodChat专用构建标签的编译中间层和没有容器引用的旧GoodChat镜像，保留正式与回退镜像，不清理其他项目或数据卷。

需要手动重新构建当前提交时可添加 `--force`。不要手动编辑 `app` 内已跟踪文件，否则脚本会中止以保护本地改动。

## 版本发布与启动检查

平台管理员可新增或编辑三段数字版本、更新描述、Windows下载地址、Mac下载地址及可选APK下载地址。只有勾选发布的记录才公开；下载链接要求HTTPS。当前没有APK，留空即可，下载页不会展示APK按钮。

- 公开列表：`GET /api/v1/public/client-releases`
- 启动检查：`GET /api/v1/public/client-releases/latest?platform=mac&current_version=0.1.1`
- 版本管理：`GET/POST /api/v1/platform/client-releases`、`PATCH /api/v1/platform/client-releases/{id}`，要求平台管理员。

服务器按数字比较版本。最新版本必须同时大于客户端版本和 `0.0.1` 才要求强制更新，避免相同版本反复被拦截。每个平台只选择该平台下载地址不为空的最新已发布版本。

客户端每次启动连接所选服务器后先检查版本；切换服务器会清除原检查结果。检查失败不进入客服业务，用户可以重试或更改服务器。强制更新页面提供下载和重新检查；本机Go层也会拦截业务API和身份绑定，无法通过普通前端跳转绕过。

首个线上版本为 `0.1.1`，默认服务器 `https://goodchat.58it.cn`。Mac为Universal DMG，Windows为amd64 ZIP。二者复用同一套代码与打包脚本，版本号和默认服务器均可在构建时指定。当前为开发签名Mac包和未签名Windows包，尚未完成Apple公证及Windows代码签名。

## 同域装修模块

装修直接使用 `https://goodchat.58it.cn/render/{release_id}`，包内资源使用 `/assets/` 和 `/preview-assets/` 的版本与短期令牌路径，不需要子域名、新域名或新证书。`SUPPORT_CODE_ORIGIN` 默认采用官网地址；当前生产明确配置为官网地址，已移除此前暂停装修的开关。

所有装修HTML响应均设置 `Content-Security-Policy: ...; sandbox allow-scripts`，各处iframe也只开放 `allow-scripts`。不开放 `allow-same-origin`，使同域URL在浏览器中仍处于独立的不透明来源，不能读取主站Cookie、localStorage或父页DOM。即使直接打开HTML，也有响应级沙箱约束。

静态包的脚本、样式、图片和字体仅能从当前发布的固定目录读取。静态响应开放匿名CORS以支持不透明来源中的模块和字体，不开放凭据CORS；主站API保持原有鉴权与来源检查。网关向静态渲染服务转发时丢弃Cookie和Authorization。装修脚本的网络请求、子框架、表单和工作线程仍被CSP阻止。

访客消息仍通过受限MessageChannel交给可信父页处理。不透明来源消息的origin为字符串null，因此父页同时校验精确iframe窗口、协议版本、发布编号与一次性随机数；编辑预览还校验短期编辑随机数。父页发送到已定位的不透明窗口时必须使用通配targetOrigin，但不发送登录凭据，业务调用仍只授权当前会话及可见消息、附件。

验证包括真实浏览器的Cookie/存储/父DOM/网络阻断和模块、样式、图片、SDK桥接，以及真实PostgreSQL的同域预览、发布和访客入口绑定。较早的跨域配置仍兼容原有版本子域URL，但生产当前无需此配置。
