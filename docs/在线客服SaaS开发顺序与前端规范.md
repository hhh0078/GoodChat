## 1 三份文档的职责

需求文档定义角色、业务行为、参数、边界和验收；技术文档定义 PostgreSQL 数据、身份权限、接口、实时事件与隔离；本文定义先做什么、每步完成条件和统一的前端实现方式。实现中发现冲突时，先核对用户最新要求，再同步修正文档，不依赖页面临时逻辑改变服务端规则。

v1.2 新增确认包括永久免费基础版 0 元长期 2 个客服坐席、待接受邀请预占、平台版本定价与实际开通、访客进入异步回调、记录统计独立页及单应用容器复用既有 PG/Redis。此前新增确认包括官网 SEO、邮箱注册登录、首次注册创建租户管理员、邀请或添加租户管理员与客服，以及 React Ant Design 统一 UI。前版 Vue 技术建议由此更新为 React、Next.js、TypeScript 与 Ant Design。

## 2 开发前准备

检查当前目录和已有文件，保留已交付的旧版 Word，更新当前 Markdown 源稿并生成新版本。开发前创建 Git 分支；已有仓库优先遵守现有远端与分支，空目录先建立本地仓库，远端缺失时继续本地开发并记录待推送原因，不向其他项目远端推送。

安装前检查 npm 和 Go 国内镜像。锁定包版本并提交锁文件，不将 node_modules、运行日志、上传内容、数据库文件或真实密钥加入 Git。示例配置只放变量名称和无效示例值。所有新源文件写中文作用说明，新函数和组件写中文标准注释。

准备一个 GoodChat 应用容器，复用已存在的 local_postgres（PostgreSQL 17.4）和 jijie-redis；数据库使用 goodchat_saas 独立库、Redis 键使用 goodchat: 前缀，不额外创建数据库或 Redis 容器，不操作其他项目库与键。Next.js standalone 与 Go 在同一镜像运行，持久附件独立挂载，构建与运行环境变量边界写入部署说明。

.local SMTP 私有配置已获用户授权参考 GoodHR 复用，只作运行时私有配置，不写入 Git、文档或镜像。真实发信受理与收件分别验收；AI 未配置时明确暂不可用。生产域名、HTTPS、独立装修域名和真实支付渠道待配置，禁止万能码、假生成或假收款。

## 3 阶段顺序与完成条件

### 3 1 D00 文档与契约

冻结本轮需求编号、角色、服务空间、客服分组、分配池、客户分类与标签的区别。确定邮箱注册和邀请流程、链接参数结构、会话状态与消息事件格式。输出三份文档、接口目录、数据库迁移约定和待定运营参数。

完成条件是三份文档对首版范围一致；租户 AI 私有模板、完整代码装修和邮箱自动建租户均有明确规则；不存在把参考项目菜单当成新产品已完成的描述。

### 3 2 D01 工程与数据基础

建立 Go 后端、Next.js 前端、共享类型、迁移和测试目录。配置 Ant Design SSR 样式、主题、页面壳、统一 API 客户端、错误边界和中文界面。建立既有 PostgreSQL 独立库连接、迁移版本、数据库角色、中文对象注释、健康检查和请求日志；完成单应用容器、既有 Redis 前缀及持久附件约定。

完成条件是前后端可启动、构建通过、测试库迁移通过、基础错误与健康状态可观测。验证租户上下文缺失、连接池切换和事务回滚不会串租户。

### 3 3 D02 官网与邮箱身份

先实现可被搜索引擎读取的官网、功能介绍、方案、价格说明、帮助入口、隐私和服务条款页面；再实现邮箱注册、验证码登录、密码登录、找回密码和退出。参考 GoodHR 的 Mailer、SMTP 截止时间、模板和失败分类，重新实现验证码原子消费和发信限流。

首次注册在一个事务内创建用户、新租户、所有者管理员关系及默认资源。已有邮箱登录不会重复建租户；邀请入口加入原租户。平台管理员通过受控初始化产生，公开表单不接受平台角色。另接通平台主动开通租户与所有者邮箱激活邀请，稳定幂等键防止SMTP失败或超时重试重复建租户；初始未激活租户可按冷却重发原邀请。

官网首屏突出基础客服永久免费、2 个客服坐席，不作必然响应承诺。先实现公开套餐 API 与服务端价格读取，后台尚无收费版本时不编造标价；SSR 后端不可用显示配置中。

完成条件是邮箱验证码过期、重放、错用用途、超次尝试和并发注册测试通过；假 SMTP 测试与真实收件证据分开记录；官网 HTML、标题描述、canonical、robots 和 sitemap 可验证。

### 3 4 D03 租户成员与权限

实现租户设置、成员列表、邀请管理员、邀请客服、角色、客服分组、分配池、技能和接待上限。实现邀请撤销与重发、待激活成员、停用和移除、最后一名管理员保护、设备会话撤销；同步完成免费2席、纯管理不占、待接受可接待邀请预占及并发最后一席保护。

完成条件是管理员与客服权限独立、跨租户请求被拒绝、邀请不能自行改角色、已登录成员被停用后实时与 API 权限同时失效。

### 3 5 D04 链接与客户资料

实现多个接入链接、二维码、来源分类与标签、分组或分配池或客服目标、链接参数白名单和模拟预览。支持姓名、头像、手机号及 JSON 上下文的查询参数、初始化请求或短票据。完成客户资料、自定义字段、标签分类、批量操作与访问轨迹；接通租户 visitor.entered 回调 URL、启停、字段开关、签名、测试、日志及原任务重试。visit_id 重试去重，恢复旧咨询仍是一次进入，异步失败不阻聊天。

完成条件是链接组合路由可解释，错误 JSON 与超限参数有提示；未验证手机号不能读取旧客户历史；来源快照不被覆盖；客服分组、分配池与客户分类不存在字段混用。

### 3 6 D05 可靠聊天

实现访客身份、会话创建复用、文字表情、图片文件、语音消息、历史、未读已读、失败重发、附件授权和实时事件。完成访客 PC 与手机界面以及客服工作台基础接待。

完成条件是幂等、乱序、断线、补拉、内部备注隔离和已读游标测试通过；输入法、换行、粘贴截图、历史滚动和手机键盘可以实际操作。语音录制受权限或浏览器限制时有明确降级，不把提示音当成语音消息。

### 3 7 D06 分配与接待闭环

实现资格过滤、轮询、最少会话、负载比例、加权、随机、技能、历史优先、指定客服、人工领取、排队和兜底。实现确认接单、容量预留、转接、超时、拒接、关闭和离线宽限。

完成条件是多个请求竞争同一会话或最后一个名额不超额；转接确认与关闭竞态不产生两个正式接待人；严格队列顺序与配置口径一致。

### 3 8 D07 接待效率与提醒

实现双方正在输入、提示音、语音播报、站内提醒、浏览器通知、通知偏好和多标签页去重。实现个人与公共话术、欢迎语、关键词自动回复、营业时间、夜间留言、满意度和黑名单。

完成条件是提醒被浏览器限制时界面正确降级，补拉不批量响铃，正在输入会过期且不泄露草稿；欢迎语和规则回复有范围、优先级、冷却及幂等保护；黑名单保留聊天历史。

### 3 9 D08 装修模板与发布

实现基础装修、结构化拖拽、CSS、代码编辑与资源包、平台模板和租户私有模板。建立可信聊天运行层与隔离代码 iframe，完成 PC 手机预览、草稿冲突、候选版本、校验、绑定、发布与回滚。

完成条件是代码页只操作当前授权会话，不能获得管理登录态；多个链接共用与独立页面的更新关系正确；两个并行发布不能使旧任务覆盖新版本。

### 3 10 D09 租户自助 AI

实现租户从我的模板发起 AI 创建、任务进度、结构化与代码两种结果、局部修改、失败取消、用量和预览发布。AI 产物从创建起就归当前租户，能复制、复用和创建多个独立页面。

完成条件是实际配置的模型可完成生成到链接上线闭环；模型不可用时任务真实失败且线上版本不变；迟到结果与并发编辑不会覆盖新草稿。不以本地假输出宣称真实 AI 验收通过。

### 3 11 D10 运营与上线验收

补齐独立聊天记录页与独立统计页、元数据和正文分开导出、Asia/Shanghai 时区及去重归属、审计、额度、到期、备份恢复和可观测性。平台可配置版本价格分、有效期、坐席、功能及公开状态；租户申请与实际付款、平台确认开通分开，付费必须核对实际收款依据，不以成功提示冒充支付。到期降级不删除历史。执行三端角色、不同浏览器、移动端、真实邮件、真实模型、故障恢复和压力测试。

完成条件包含单应用容器连接既有 PG/Redis、私密 SMTP 不入镜像、升级与坐席竞态、回调异步失败及签名、记录统计口径的专项证据。需求验收矩阵逐项有通过证据或明确的未完成状态，部署配置与回退步骤可执行。没有实际试验的容量、收件、通知和设备能力不能标记已验收。

## 4 统一前端技术规范

### 4 1 技术栈

官网及应用采用 Next.js App Router、React、TypeScript 和 Ant Design。管理与客服 UI 统一使用 antd，图标统一使用 Ant Design Icons。通过 Ant Design 官方 Next.js SSR 接入方式保证首屏样式稳定。需要移动布局时优先使用同一组件体系和响应式 CSS，不混入第二套管理 UI 库。

官网主要内容由服务端或静态生成输出；登录、编辑器、聊天等交互区按需要使用 Client Component。不要把整个站点根布局都改成仅客户端渲染。品牌暂使用中性的在线客服产品名称，域名与正式品牌通过配置替换。

### 4 2 页面与目录

建议目录分为 app 路由、components 通用组件、features 业务模块、lib API 与会话工具、styles 全局主题、types 共享契约。业务请求集中在 API 层，不在多个组件里重复拼接地址、解析错误或获取租户上下文。

官网、身份页面、平台管理、租户管理、客服工作台、访客页分别使用清晰布局。权限控制由后端执行，前端菜单与按钮按同一能力清单显示。路由守卫只改善体验，不作为数据权限边界。

### 4 3 视觉与组件

| 项目 | 统一要求 |
| --- | --- |
| 品牌色 | 用户于2026-10-28确认银白与钴蓝科技风，通过统一主题 token 配置；以 docs/designs/2026-10-28-cobalt 的已选图稿为当前依据，租户自定义装修保留其配置 |
| 禁用样式 | 不使用蓝紫渐变，不混用多套按钮和表单风格 |
| 间距 | 基础 8 像素体系，常用 8 16 24 32 |
| 字体 | 系统中文无衬线，正文 14 至 16 像素，数字和时间格式统一 |
| 布局 | 管理端左导航加页标题与内容区，聊天端保留会话列表和对话主区 |
| 按钮 | 同一区域一个主要动作，危险动作明确文案与影响范围 |
| 表单 | Form 统一标签和校验，必填、帮助文字、提交状态一致 |
| 列表 | Table 统一筛选、分页、空状态、批量选择与操作权限 |
| 弹层 | 简单确认使用 Modal，资料和配置编辑优先 Drawer 或独立页 |
| 反馈 | 成功、失败、警告按统一 API 错误规范，保留可操作恢复入口 |

平台模板遵循产品色彩要求；租户可以在允许范围内定制访客页。自定义 CSS 的作用域只限装修画布，不能污染管理端或客服工作台。

### 4 4 交互与状态

每个数据页面至少定义加载、空数据、错误、无权限、正常和提交中状态。提交禁用只用于防止重复动作，同时展示处理状态。按钮点击后必须执行真实动作或显示明确的不可用原因，禁止用成功提示代替保存。

列表筛选保留在页面状态或 URL 中，翻页不丢筛选；删除后校正页码。编辑草稿有未保存提示，保存冲突保留用户内容。枚举、时间、金额、文件大小、电话脱敏和空值展示集中格式化。

### 4 5 响应式与可访问性

验收至少包含 360、390、768、1024、1440 像素宽度。电脑客服采用多栏，窄屏采用列表与会话切换，不能把桌面三栏强行压缩。移动访客页处理安全区域、输入法键盘、旋转、返回与图片预览。

表单可键盘操作，焦点可见，图标按钮有文字说明或可访问名称。弹层管理焦点，状态不只靠颜色。中文输入组合阶段按回车选词不能发送消息。图片有替代说明，长文件名和长 JSON 字段不撑破页面。

### 4 6 实时与缓存

服务端是会话、分配、权限与未读的事实来源。客户端状态按事件 ID 幂等更新，历史补拉和即时事件合并去重。浏览器多标签页通过本地协调减少重复提醒，但服务端不依赖某个标签页永久存在。

缓存键包含租户和访问范围，退出登录或切换租户后清理受限缓存。验证码、登录令牌、聊天正文和客户资料不放入公开 HTML、公共缓存或分析埋点。

## 5 邮件与官网专项要求

注册、登录、密码重置、邀请邮件使用不同用途和模板；验证码过期、使用和失败次数由后端判断。生产 SMTP 配置缺失不能回退万能码或在响应里返回验证码。发送结果不确定时先查询任务记录，避免无条件重复发送。

官网为公开路由提供唯一标题、描述、canonical 和真实内容；生成 sitemap 与 robots，配置 Open Graph 与结构化信息。登录、管理端、客服端、访客聊天链接和带个资参数页面不进入 sitemap，并设置适合的 noindex 规则。SEO 文件不替代实际鉴权。

## 6 验证与阶段记录

Go 执行单元与真实 PostgreSQL 集成测试；前端执行类型检查、构建、必要的组件测试和浏览器验收。安全与并发逻辑必须测边界，不为只重复实现的简单展示写无意义测试。

每个阶段记录实现范围、运行命令、结果、截图或接口证据、未覆盖项和需要的外部配置。开发中使用的测试数据明确标记，正式功能不展示虚构在线用户数、付费客户数、服务承诺或 AI 成功结果。

完成阶段后复查注释、权限、数据边界和回退；按中文提交信息提交并推送到已指定远端。发送用户要求的完成或待处理邮件，并播放对应完成提醒。持续开发期间的普通进度更新不等于阶段已经验收。
