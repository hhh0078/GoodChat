# 九语言与时区适配

本次支持 `zh-CN`、`en`、`zh-TW`、`ja`、`ko`、`es`、`pt-BR`、`fr`、`de`。语言包随版本发布，运行时不依赖在线翻译服务。保留银白钴蓝主题及现有 Ant Design。

## 访问与确认

- 官网支持 `/en`、`/de/pricing` 等语言路径，公开页面有独立元数据、canonical、九语 hreflang 和 sitemap。原有无语言路径继续可访问。
- 显式查询参数为 `lang`、`timezone`，例如 `/?lang=en&timezone=America%2FNew_York`。有效查询参数优先于语言路径、已保存偏好和设备检测。
- 两项有效时直接采用，无需确认；只有一项时仅确认缺少的项目；首次两项均缺少时从 `navigator.languages`、`Intl.DateTimeFormat().resolvedOptions().timeZone` 获取并集中确认。
- 已确认设置保存在本机，后续无需重复确认。URL 的有效选择保留于本次浏览会话；不会自动修改已有账号或企业设置。无 URL 覆盖且电脑时区发生变化时，再确认新的设备时区。
- 无效、重复、不支持的参数不会成为有效偏好；该字段进入设备检测确认流程。检测失败可手动选择，暂用英语与 UTC。时区使用 IANA 名称，不使用裸 `UTC+8` 偏移。
- 页面提供语言、时区切换入口。主动确认后同步个人设置；匿名用户保存在本机，登录后同步已经确认的字段。

## 个人与企业时区

个人语言决定界面和通知文案，个人时区决定聊天和操作时间展示。企业现有 `tenants.timezone` 继续用于报表、营业时间、自然日限额和筛选日期，不会因客服或访客切换语言、时区而变化。

注册页单独展示企业营业与统计时区，默认跟随当前个人选择，由创建者随注册信息确认。旧客户端注册保持上海时区兼容。时间点仍通过 RFC 3339、数据库 `timestamptz` 保存；纯日期和报表日历不随个人显示时区平移。价格、币种、权限、状态枚举与语言独立。

## 前端实现

- `frontend/src/i18n/`：语言协商、偏好确认、请求配置、按需加载目录、Ant Design/日期组件语言、格式化和官网链接。
- Next.js 使用 `next-intl`，官网保留服务端渲染。同步组件、异步组件和客户端分别获取当前请求或组件的翻译上下文，不在服务器共享某位用户的语言。
- 静态文字、表单校验、错误兜底、空状态、角色、状态、按钮、图表标签及辅助阅读标签进入语言目录。源码中的静态配置显式翻译；不递归翻译接口里的任意业务内容。
- 桌面网页复用相同目录、组件语言、语言时区选择器与请求头白名单。
- 固定访客 SDK 与聊天控件使用宿主选定语言、时区。已发布脚本的兼容层仅处理平台固定控件、已读标签与真实消息时间，不处理消息正文、引用、参与者姓名或商户品牌，也不增加沙箱网络权限。

## 后端协议与数据

请求使用 `X-GoodChat-Locale` / `Accept-Language` 和 `X-GoodChat-Timezone`。语言与个人时区均不参与租户授权。账号、租户仍来自认证上下文。

安全错误保留原有字段，增加消息标识、参数和实际系统语言：

```json
{
  "code": "export_limit_exceeded",
  "message": "...",
  "message_key": "m...",
  "message_params": { "p0": 10000 },
  "locale": "en",
  "request_id": "..."
}
```

`code` 保持机器判断语义；消息标识由原始模板的 UTF-8 FNV-1a 生成，变量保留原值。前后端目录同源，旧客户端可继续直接读取 `message`。内部错误仍使用安全兜底，不暴露数据库或密钥。响应通过 `Content-Language` 标记系统语言。

持久任务的 `error_message` 在受控投影中本地化，并附带 `error_message_key`、`error_message_params`；不遍历需求、模型正文、设计或用户扩展对象。状态、角色、权益等继续返回稳定代码。

- **原文保留**：客户聊天、姓名、企业名称、备注、文件名、租户话术与装修正文、未知供应商说明和历史内容。
- **平台发布内容**：套餐及公共模板可通过九个语言页签维护译文。公开读取、套餐展示和模板复制采用对应的已发布译文，缺失时保留原内容；价格、权益、原始编辑内容和历史快照保持完整。
- **邮件**：认证邮件使用当前选择，邀请与留言提醒优先采用收件人已保存语言，再使用企业默认语言。验证码、链接和企业名称作为原始变量插入。
- **导出**：表头和系统标签本地化；统计日期与时间继续使用企业时区。异步导出冻结提交语言，后续切换界面不会改变已生成文件。消息正文与自定义资料保留原文，CSV 公式防护继续生效。
- **AI 创作**：新任务冻结默认输出语言，生成说明和新增页面文案采用该语言；用户明确指定内容语言时遵循用户要求。既有品牌、业务内容和协议字段保留。

## 检查与维护

```sh
cd frontend
npm run i18n:check
npm run typecheck
npm test
npm run build
npm run desktop:typecheck
npm run desktop:build

cd ../backend
go test ./...
```

`i18n:check` 校验九语键集合、UTF-8 消息标识、前后端目录、命名变量、printf 参数、ICU 字面量和源码消息覆盖。新增系统文字必须补齐九语目录；不要用中文显示文本判断业务状态，也不要把租户业务内容送入批量翻译。

本次验收通过 3420 条九语文案检查、131 项前端测试、后端测试及认证/套餐/聊天的隔离数据库集成测试，以及网页和桌面资源构建。真实浏览器覆盖九种官网与后台语言、URL 两项齐全及单项缺失、设备确认持久化、手动切换入口和德语手机排版；生产构建另检查九种语言的首页、套餐、功能页服务端正文和 canonical，确认已有英文 Cookie 不会覆盖显式语言路径。套餐价格、公共模板复制及原始企业身份数据也通过独立接口验收。

译文采用静态生成并校订核心术语，尚未逐条通过九种语言的母语审校。数据库与浏览器验收使用独立测试账号和数据；测试邮件及替身模型不代表真实邮件送达或真实 AI 生成验收。推送主分支与线上部署状态分别报告。
