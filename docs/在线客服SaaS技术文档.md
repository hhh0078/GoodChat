# 在线客服 SaaS 技术文档

Go PostgreSQL 网页首版实现设计

版本 1.2　日期 2026年10月26日　负责人 邓云川

系统采用 Go 模块化单体与 PostgreSQL，提供平台管理员端、租户端、客服端及电脑手机访客页。所有业务权限、会话状态、消息保存和客服分配由服务端统一执行；页面装修采用结构化渲染与代码沙箱两种方式，共享模板、AI 创作、预览、发布与回滚体系。本文与需求文档 R01 至 R28 对应，用于开发设计、接口约定、数据库迁移和验收拆解。

## 1 架构与技术选择

### 1 1 应用结构

产品品牌为 GoodChat，首版部署固定为一个应用容器并复用已有基础服务。工程划分为 Go 服务、管理与客服网页、访客可信运行层、可视化编辑器、自定义代码渲染器和共享协议定义。三端业务按权限分开路由；访客入口与管理登录分开部署来源。首版一个 Go 进程可承担 HTTP API、WebSocket 和后台任务，任务执行逻辑与请求处理逻辑独立成模块。

请求链路为浏览器或后续客户端进入 HTTPS 网关，调用认证后的 Go API；Go 使用 PostgreSQL 保存事务数据，使用对象存储保存附件与装修资源。持久消息、分配和任务状态以 PostgreSQL 为准。Redis 可用于共享在线状态、限流和多实例通知，缓存与通知丢失时仍能从持久数据恢复。

前端按用户要求统一使用 React、Next.js、TypeScript 与 Ant Design，官网采用服务端或静态输出满足SEO，管理、客服与访客交互共享接口及主题规范。后端采用Go标准HTTP能力与维护中的WebSocket库，PostgreSQL驱动采用pgx。依赖在开发启动时核对并锁定；前端细则见开发顺序与前端规范，官方依据见T07至T11。

### 1 2 模块职责

| 模块 | 主要职责 |
| --- | --- |
| identity tenant | 平台账号、租户成员、角色、设备会话、支持授权 |
| access contact | 服务空间、公开链接、访客身份、签名业务身份、来源轨迹 |
| conversation | 会话生命周期、参与者、历史可见与状态变更 |
| routing | 资格过滤、优先级、分配算法、队列、接待容量与转接 |
| messaging | 消息幂等、序号、历史、已读、附件与实时事件 |
| decoration | 页面结构、代码包、素材、预览、校验、发布与绑定 |
| templates ai | 平台模板、租户模板、AI 任务、生成版本和用量 |
| operations billing | 套餐价格与快照、坐席预占、开通审计、统计、后台任务与导出 |

### 1 3 后续客户端

Web、macOS、Windows、Android 客服端复用版本化 API、实时事件、身份与权限模型。首版定义设备标识、访问与刷新凭证、撤销、多设备在线和已读同步。客户端本地缓存、系统通知、后台保活、文件选择与安全凭证存储分别适配。

原生框架在对应客户端启动开发时选定；服务端不依赖浏览器专属逻辑。网页与原生客户端都以服务端接待状态为准。断线重连协议与数据库持久化能力先于客户端框架实现。

## 2 身份认证与租户隔离

### 2 1 身份类型

平台账号保存登录身份；租户成员记录同一账号在某租户的角色与权限；客服在线状态和容量属于租户成员。访客使用独立的访客身份与凭证，不能取得成员凭证。一个人加入多租户时，各租户接待状态、权限和消息分别管理。

公开链接标识仅解析入口，不是聊天历史访问密钥。服务端通过入口记录确定 tenant_id 与 service_space_id，再签发限定访客与会话范围的凭证。商户业务身份采用服务端签名断言，包含租户应用、外部用户标识、过期时间和防重放标识；公开参数不覆盖已验证身份。

管理网页登录建议使用 Secure、HttpOnly、host-only Cookie，并对写操作执行 CSRF 和 Origin 校验。访客运行层使用短期、最小范围凭证。WebSocket 握手检查来源与身份；如浏览器使用一次性连接票据，票据短期有效且使用后失效，访问日志不得记录票据。原生客户端后续使用同一身份服务的设备令牌与刷新流程。

### 2 2 数据与服务边界

租户业务表带 tenant_id，查询及授权均从认证上下文获得租户，不直接信任请求体或自定义页面传来的值。消息、附件、缓存键、WebSocket 订阅、后台任务、导出和审计都携带相同边界。

业务关联采用复合键约束。例如 messages 的 tenant_id 与 conversation_id 共同引用 conversations 的 tenant_id 与 id，从数据库层阻止跨租户关联。不同租户外部客户标识相同，不产生共享客户或共享历史。

### 2 3 PostgreSQL 行级安全

建议对租户业务表启用 Row Level Security，并配置 USING 与 WITH CHECK；应用运行角色与迁移角色分离。运行角色不得具有超级用户或 BYPASSRLS 权限，且不作为业务表所有者；需要时启用 FORCE ROW LEVEL SECURITY。RLS 的角色例外依据官方说明，见 T01。

使用连接池时，每次业务事务在认证后设置事务级租户上下文，例如通过 set_config 的事务局部参数传入当前租户。事务内完成所有相应查询；上下文缺失时拒绝访问。避免使用长期留存在连接上的租户变量。平台级租户管理与公共模板使用独立的受控访问路径，不能接受前端指定绕过标志。

RLS 是应用授权之外的补充。查询注入、错误的高权限数据库角色、跨租户文件路径和实时推送都需要各自防护，不能由 RLS 单独解决。

## 3 PostgreSQL 数据模型

### 3 1 数据约定

主键建议使用 UUID，业务时间使用 timestamptz，保存 UTC 时间并按租户时区展示。消息与事件序号使用 bigint，API 中编码为十进制字符串，避免 JavaScript 数字精度损失。金额和用量账目使用明确单位的整数或定点数，不使用浮点金额。

页面 Schema、规则配置与渠道扩展字段使用 jsonb 并包含 schema_version；关键查询、权限、状态和关联字段使用独立列。表与列均使用 PostgreSQL 的 COMMENT ON TABLE 和 COMMENT ON COLUMN 添加中文说明，迁移文件头部说明目的、影响范围和回退办法，语法依据见 T03。

### 3 2 核心实体

| tenant_memberships roles | 租户成员、角色、权限与禁用状态 |
| service_spaces | 租户内服务范围、默认页面与接待策略 |
| agent_groups group_members | 技能组、成员、技能与可接待范围 |
| agent_runtime | 租户成员、接待状态、容量、占用、在线有效期 |
| access_links access_visits | 公开入口配置、有效期、来源与访问轨迹 |
| contacts contact_identities | 租户客户与匿名、业务账号、外部渠道身份 |
| conversations | 独立咨询、来源快照、状态、当前接待与序号 |
| conversation_assignments | 分配、待接单、接待、释放时间与原因 |
| agent_capacity_holds transfer_requests | 当前接待及转接目标的容量占用、预留与确认状态 |

全局平台实体与租户实体使用明确分表或明确的访问策略。平台公共模板复制到租户后，tenant_templates 记录来源模板和来源版本，不使用可空 tenant_id 混合所有权限。

### 3 3 会话字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id tenant_id service_space_id | uuid | 联合关联和租户范围校验 |
| contact_id created_entry_id | uuid | 客户及创建入口，来源不可被新访问覆盖 |
| status | text | queued、assigned、active、closed |
| current_assignment_id | uuid 可空 | 当前有效接待，与接待表保持事务一致 |
| next_event_seq version | bigint | 事件序号与乐观并发版本 |
| routing_policy_snapshot | jsonb | 创建或本次重分配生效的规则快照 |
| created_at closed_at | timestamptz | 独立咨询的开始与关闭边界 |

建议对 tenant_id、service_space_id、contact_id 建立部分唯一索引，限定 queued、assigned、active 状态，保障同一服务空间同一客户只有一个进行中会话。并发创建冲突时读取已有会话。客服分配表对 tenant_id、conversation_id 在 released_at 为空时建立部分唯一索引。

### 3 4 消息与事件字段

| 实体字段 | 类型 | 规则 |
| --- | --- | --- |
| messages id conversation_id sender_id | uuid | sender_kind 区分访客、客服与系统 |
| messages client_message_id | uuid | 发送前生成，重试保持不变 |
| messages message_type payload | text 与 jsonb | 正文结构按类型校验，不接收任意 HTML |
| messages event_seq created_at | bigint 与 timestamptz | 保留对应事件位置与提交时间 |
| events id conversation_id seq | uuid 与 bigint | 会话内序号唯一，包含事件类型与结构版本 |
| read_cursors participant_id last_read_seq | uuid 与 bigint | 单调更新，多设备共享参与者进度 |
| outbox event_id attempts lease_until | uuid 整数 时间 | 用于认领、重试与崩溃恢复 |

消息幂等唯一键建议为 tenant_id、conversation_id、sender_kind、sender_id、client_message_id。附件引用同租户且属于当前发送者可使用范围，不能通过猜测对象标识挂载其他人的文件。

### 3 5 索引与增长

会话列表按 tenant_id、status、updated_at、id 建索引，历史按 tenant_id、conversation_id、seq 使用游标分页；队列按租户、组、有效优先级、入队时间与稳定标识排序。所有分页都带稳定的次级排序字段。

首版使用普通消息与事件表；分区需结合真实数据量再实施。若将来按时间分区，先重新设计全局幂等键与唯一约束，不能直接假设跨分区唯一约束仍然成立。保留与清理任务分租户执行，遵守套餐政策和审计要求。

## 4 接入与会话生命周期

### 4 1 链接解析与身份建立

访问公开 entry_key 后，API 返回租户允许公开的品牌、服务状态、页面发布标识与访客认证引导。绑定模式为 FOLLOW_PAGE 或 PIN_RELEASE；前者读取页面当前发布指针，后者固定到明确版本。版本与资源使用内容哈希或不可变路径缓存。

访客首次咨询时，在租户和服务空间范围内查找进行中会话，事务创建或复用。数据库唯一约束处理多标签页竞态。进入其他链接只新增访问轨迹；既有会话、接待归属和来源快照不自动改写。

既有会话恢复优先于新入口的指定客服、技能与营业规则。访客选择按新入口重新咨询时，通过显式且幂等的结束再新建操作完成，部分唯一约束阻止短时重复会话；来源切换本身不触发该操作。

### 4 2 状态转换

queued 可以被取消或分配；确认模式进入 assigned，接单后进入 active；自动模式直接进入 active。拒接或预留超时使 assigned 回到 queued。active 可转接或关闭，closed 后再次咨询创建新的会话。

自动模式转接目标为客服时，保留旧分配直到目标名额成功占用，再原子切换。确认模式创建 transfer_request 与目标 capacity_hold，原分配和会话 active 状态保留；目标确认后结束旧分配、释放原占用、激活目标占用并创建新分配。拒接、超时或取消只释放目标预留。transfer_request 对每个会话只允许一条未完成记录，不能形成多个并行目标。转接到队列时执行显式动作，释放当前分配并回到 queued。网络连接状态属于运行状态，和会话状态分别处理。

关闭、取消、转接、超时等写接口接受幂等键与预期版本。先验证当前身份和访问权，再查幂等记录并核对请求摘要；已完成动作返回原结果，只有新动作才检查预期版本和当前状态。权限已撤销时仍拒绝，不能由旧幂等键绕过。所有变更写入会话事件和审计，避免后台任务与用户操作相互覆盖。

### 4 3 访客进入异步回调

租户设置包含 enabled、url、events、include_context、include_phone、version 及 secret_configured，敏感字段和业务上下文默认关闭。首版只接收 visitor.entered。一次访问以 visit_id 去重，和新建会话的 conversation.created 区分；初始化重试沿用 visit_id，新访问另生成。访问记录与待投递事件在同一事务内保存，外部 HTTP 由独立可靠任务执行，失败不回滚已完成的正常聊天。

投递保留稳定事件、访问编号、配置版本、目标、状态、尝试次数及脱敏响应，采用超时、有限重试与退避；手工重试针对原任务。签名密钥加密保存并仅轮换时展示一次，接收方按原始体、时间窗和事件编号验证及去重。测试事件明确标记，不生成虚构业务量。公开 HTTPS 目标每次解析与连接均检查内网、环回、云元数据、DNS 变化和重定向绕过，限制并发、响应体和连接时长。

## 5 分配与并发控制

### 5 1 策略模型

分配配置包括 eligibility、preferred、algorithm、fallback 和 timeout。eligibility 表达服务空间、组、技能、有效账号与在线容量条件；preferred 表达历史或指定客服优先；algorithm 选取一个主算法；fallback 显式允许兜底范围、排队或留言。

轮询与加权轮询需要保存策略运行状态。建议按租户和接待组建立策略锁定行，在事务内更新游标或加权分数。最少会话、最低负载和随机使用同一套容量提交路径。人工领取同样执行原子分配，不能另写无锁流程。

### 5 2 原子分配流程

1. 开启事务并设置租户上下文，先锁定涉及的队列或策略分片行，再按优先级、入队时间与稳定标识选择并锁定下一会话，确认其状态和版本。
2. 读取本轮规则快照与受锁保护的轮询或加权状态。人工领取也先取得对应队列分片锁，再锁定请求会话。
3. 选出候选客服，锁定其 agent_runtime 行，再次检查权限、心跳租期、接待状态与容量。
4. 容量满足时创建唯一的未释放接待记录，增加占用，更新会话状态与策略状态。
5. 同事务写入事件和 outbox，提交后才推送分配结果。
6. 无候选人时保留持久队列记录，按兜底设置下一次处理条件，不在事务内无限循环。

容量可以通过行锁保护后更新，或使用带 current_load 小于 capacity 条件的原子更新并检查返回结果。任何一步失败都整体回滚。待接单也占用名额，接单、拒接与超时按同一条接待记录处理。

SKIP LOCKED 适用于并发队列消费者，但会跳过已锁定记录，不能由此承诺严格公平排序，见 T02。首版需要严格轮询或严格同优先级先来先服务时，应串行锁定相应策略行或队列分片行；高吞吐策略可以选择近似公平并明确口径。

### 5 3 转接关闭与锁顺序

所有相关操作采用固定锁顺序：按稳定标识排序的队列或策略分片行、会话、按稳定标识排序的客服容量行、接待记录。入队、出队、关闭、转接和超时只要触及队列均遵守相同顺序，不能先锁较晚会话再竞争队列锁。转接涉及两个队列或客服时按同一稳定顺序加锁；路由版本在加锁后改变则退出并有限重试，不逆序补锁。

接待与目标预留统一关联 agent_capacity_holds，held 和 active 均占用名额，released 不占用。确认转接只改变目标占用状态，不重复加一；同事务释放原占用。关闭会话同时取消未完成转接并释放相关占用。释放动作只允许从未释放状态进入 released，实际变更成功才减少容量，防止重复关闭或超时使占用为负。并发修改客服上限时，已占用可暂时大于新上限，但不能继续新增。周期性对账以所有有效 capacity_hold 为准，包含待确认转接，差异告警后按审计流程修复。

### 5 4 在线与超时任务

在线状态以设备连接和心跳租约综合计算。建议心跳间隔 15 秒、在线租期 45 秒；这是初始工程参数，应通过网络测试调整。是否上班、是否可接待与是否存在有效连接分别存储。任何最后连接消失都先停止新分配，再执行需求文档规定的已有会话宽限。

超时任务在 PostgreSQL 持久化到期时间，任务认领使用租约和有限重试。执行前重新检查会话与接待版本。进程重启后从过期任务恢复，不能只依赖内存定时器。

## 6 消息与实时协议

### 6 1 发送提交

客户端先生成 client_message_id，并在重试中复用。服务端验证当前发送者身份与访问权后先查询幂等结果；已有成功记录且内容摘要一致时返回原消息，即使会话此后已结束。只有新发送才检查会话是否允许写入，锁定会话序号行，插入消息、事件与 outbox。提交成功后返回 accepted，响应包含消息 ID、会话序号与服务端时间。

重复幂等键返回同一已保存消息；同一键携带不同内容返回冲突。事务内不调用外部渠道 API，不等待 WebSocket 写入。若提交成功但响应丢失，客户端重试仍取得同一消息。

### 6 2 投递与恢复

outbox worker 以短事务认领可执行任务并设置租约，提交后完成网络投递，再记录完成。崩溃可能发生在实际发送后但标记完成前，因此采用至少一次投递与事件 ID 去重，不承诺端到端绝对恰好一次。

WebSocket 用于及时通知，PostgreSQL 消息与事件用于恢复。事件包含 protocol_version、event_id、conversation_id、seq、audience、event_type 与 payload。seq 使用字符串编码，audience 区分访客可见、客服内部与指定参与者。内部备注及其载荷不得推送给访客。

补拉返回可见事件、next_cursor 与服务端扫描水位；游标由服务端生成并绑定当前授权范围，允许跨过无权查看的内部事件。客户端只持久化完成处理后的服务端游标，不要求相邻可见事件的 seq 连续，也不自行把最大已见 seq 当成恢复位置。实时提示可能乱序或丢失，补拉响应负责确认该扫描范围已经完整处理。

重连先取得会话快照和同步基准，再补拉并合并缓冲事件；订阅与快照之间通过游标消除竞态。补拉使用 after_cursor 分页，接收重复事件时按 ID 和序号幂等更新。权限范围改变或事件被清理时返回 resync_required，引导客户端重新读取快照与授权游标。

### 6 3 送达已读与多端

accepted、delivered 与 read 分别表示持久化、授权终端确认与参与者阅读。已读游标只能单调向前，并校验消息实际属于本人可见会话。多端同步共享账号在当前租户的阅读进度，单个设备在线不等于所有设备都收到。

客户端网络断开后显示离线和重试状态；不能在没有终端回执时推断已送达。后续外部渠道没有相应回执时显示平台受理或未知状态，保留渠道能力差异。

### 6 4 附件

附件使用服务端授权上传，保存租户、上传者、用途、对象路径、摘要、大小、内容类型和检查状态。完成上传后验证实际大小与内容类型，文件名仅作显示，禁止作为可执行路径。附件下载重新验证会话与租户授权，签名地址短期有效。

装修素材与聊天附件分别设置用途和访问策略。动态 SVG 或可执行文件按策略拒绝、清洗或转换；危险类型不以内联方式展示。对象键和日志中不直接包含客户敏感内容。

## 7 装修渲染与代码隔离

### 7 1 两种渲染器

结构化渲染器读取版本化 Page Schema，覆盖基础设置、组件树、设计变量、PC 与手机断点、资源引用和自定义 CSS。基础设置编辑同一个设计结构。组件注册表声明属性、版本、允许行为与必须能力，禁止通过配置注入任意 JavaScript。

代码渲染器接收静态 HTML、CSS、JavaScript 与资源清单，不执行租户服务端程序。两者共享 Page、Draft、Release、Asset 和 Binding 模型，发布时产生不可变快照。结构化页可继续拖拽；代码页保留源码编辑，二者转换只通过显式复制与支持的转换流程。

### 7 2 可信运行层与独立站点

访客页面由可信运行层负责认证、会话、WebSocket、上传与恢复；租户自定义界面在独立注册域名的 iframe 中运行，只通过有限桥接显示和操作当前访客会话。平台管理 Cookie 使用 host-only，代码站点不提供任何平台登录接口。

例如平台使用 support.example，代码静态站点使用 supportusercontent.example。示例域名用于说明隔离关系，实际域名在部署时配置。代码发布建议使用独立发布来源，避免不同租户代码同源共享存储。

首版选择跨来源 iframe，sandbox 仅开启确有需要的 allow-scripts 与 allow-same-origin，必须保证子页与可信父页永不同源。不得把租户代码直接写入管理页面 DOM，也不得将用户代码 srcdoc 与同源权限组合使用。此处 sandbox 例外与来源要求依据 WHATWG，见 T04。

### 7 3 聊天桥接

允许的桥接操作仅包括读取公开页面配置、读取当前授权会话与消息、发送当前访客消息、请求平台上传交互、订阅状态、调整容器尺寸和打开经过校验的链接。具体租户、访客与会话由可信运行层确定，不接受子页自行扩大范围。

结构化页面及自定义 CSS 同样在独立渲染来源内运行，不向可信管理 DOM 注入样式。首版 SDK 使用 getState、sendText、typing、upload、download、read 与 subscribe；下载仅限当前可见未撤回附件，父层带授权取 Blob，不将令牌放入 URL。消息序号和已读位置保留字符串，实际可见且滚到底才上报。

初始握手检查精确来源、event.source、一次性握手值、协议版本和数据结构，通过后建立专用 MessageChannel。每个请求包含请求 ID、方法、参数和结果状态，执行参数长度与频率限制；页面导航、重载、版本切换或身份撤销时废止旧通道。来源校验与消息结构依据见 T05。

桥接不提供获取访问令牌、任意 HTTP 请求、读取后台数据、修改租户配置或执行父页代码的能力。子页仅获得当前访客被授权展示的数据，读取旧会话仍需服务端检查。用户代码为了绘制聊天必然能看到桥接交付的当前消息，不能将沙箱描述为对所有聊天内容完全不可见。

### 7 4 资源与执行限制

代码包发布时校验目录穿越、压缩炸弹、文件数量、单文件与总体积、文件类型、资源引用、桥接版本和依赖。首版接受无需服务器构建的静态资源包；不在 Go 主服务中执行租户构建脚本、安装包或任意命令。

代码来源响应设置限制性 CSP，分别约束 script-src、style-src、img-src、font-src、connect-src、frame-src、form-action、base-uri 与导航能力。资源优先上传到受控存储，外链走明确白名单。connect-src 可以限制常见脚本网络接口，但不能替代其他资源与表单限制，见 T06。

隔离能够限制平台权限暴露，不能保证阻止所有 CPU 占用或恶意界面行为。发布预览、基础能力检查、异常监测、版本禁用和默认聊天入口共同处理风险；真正恶意脚本导致浏览器冻结的情况需要专项测试。

## 8 模板与发布模型

### 8 1 模板归属和复制

平台模板与租户模板分开管理。平台模板版本不可变；套用时复制出本租户模板或页面，保存 source_template_version_id。租户 AI 创作从一开始分配 tenant_template_id，生成状态与编辑状态都在本租户内，不经公共模板库中转。

租户私有模板建立 tenant_id、owner_membership_id、名称、封面、render_mode、当前草稿、当前可用版本和状态。模板可用于创建多个页面，页面复制后不共享可变草稿。一个页面可被多个链接绑定，发布时展示受影响链接。

平台模板更新创建新版本，租户主动复制升级；普通下架只影响新选择。安全禁用某发布版本记录原因与操作者，切换到明确的可用版本或基础页面，不删除消息或会话。未经租户主动授权，私有作品不能成为平台公共模板。

### 8 2 发布流水线

草稿保存使用 version 或 ETag 乐观锁。创建发布任务时固定 draft_version、内容摘要、资源清单和期望线上版本，形成不可变候选快照。后续静态校验、资源冻结、隔离预览和基础能力测试全部针对该候选，编辑中的新草稿不会改变其内容。资源写入成功和校验完成后才创建 Release，并以乐观锁事务切换页面指针或链接绑定；期望线上版本已变化时返回发布冲突，保留候选供重新确认，避免旧任务后完成覆盖新发布。

发布与回滚使用幂等键，回滚同样检查期望线上版本。链接批量切换在一个受限数据库事务内完成；影响大量链接时采用独立发布任务并展示进度，不能静默部分成功。发布日志保留源草稿、版本、资源摘要、检查结果、操作者和影响链接。

缓存键包含租户、页面与发布版本，公开配置缓存另设短期或显式失效策略。当前发布指针更新后发送失效通知；旧不可变资源继续可读取，以保证正在咨询的页面可运行。资源清理先检查所有已发布和回滚保留版本引用。

## 9 租户自助 AI 模板

### 9 1 创建与任务状态

租户选择 AI 创建时，先校验权限与额度，在事务内创建本租户模板、初始草稿和 AI 任务，提交后由 worker 调用模型。任务包括 tenant_id、操作者、template_id、输入摘要、素材引用、目标模式、模型配置版本、幂等键和用量记录。

任务状态包括 queued、running、validating、succeeded、failed、cancelled。租户可以查询进度，任务结果不依赖浏览器长连接存活。取消任务增加版本或取消标记，迟到结果只有在任务与目标草稿版本仍匹配时才允许写入。

### 9 2 生成结果

可视化模式生成符合 Page Schema 的组件、样式、文本和资源引用，代码模式生成符合静态资源包约定的 HTML、CSS、JavaScript。模型通过供应商适配层调用，返回值作为不可信输入，先做结构、资源、容量和桥接能力校验，再进入隔离预览。

AI 可进行整页生成、局部修改和多次版本迭代。输入包含 base_draft_version 与修改范围，生成完成后若原草稿已经更新，保留结果为候选版本并提示合并，不能覆盖用户的新编辑。发布仍由拥有发布权限的租户成员执行。

### 9 3 用量与供应商

平台供应商密钥只在服务端。租户配额在任务创建时预占并发与预算，结束时按实际供应商用量结算；不确定是否已计费的超时任务记录待核对，不能无限重试或重复扣费。AI 账目具有任务级唯一约束，模型调用与本地状态分开审计。

设置单任务超时、重试上限、供应商熔断和租户级并发。供应商不可用只影响创作，已发布访客页继续运行。首版通过平台统一配置模型，是否允许租户自带密钥后续单独确定。

租户主动上传的设计参考图与品牌素材可以用于生成；不默认发送聊天正文、客户资料或认证数据。远程参考图片由受控下载器获取，限制协议、大小、重定向与目标网络，阻止访问内部地址。

## 11 部署运维与容量

### 11 1 首版部署

仅部署一个 GoodChat 应用容器，包含 Next.js standalone 网页产物与 Go API、WebSocket、后台任务及独立代码渲染监听。平台、可信访客父层和隔离装修来源保留安全边界，独立域名经 HTTPS 网关路由到必要监听；不同端口不能替代生产 Cookie 域隔离。生产域名与证书待最终配置，macOS 是开发环境及后续客服客户端目标之一。

复用现有 local_postgres（PostgreSQL 17.4），仅使用 goodchat_saas 独立库；应用使用最小权限账号，迁移另用受控权限。复用 jijie-redis，所有键使用 goodchat: 前缀并包含相应租户范围，不创建额外 PostgreSQL 或 Redis 容器，不修改其他项目数据与键。附件与必要加密配置挂载持久目录，重建镜像不覆盖，备份恢复包含独立库及文件引用。

前端 API 和 WebSocket 同源转发到镜像内 Go 服务。Next rewrites 的 BACKEND_URL 在构建时写入产物，构建参数和运行时变量分开说明，不能假定运行时改环境会重写目标。.local SMTP 私有配置经用户授权参考 GoodHR 复用，依赖运行时安全注入；不进入 Git、镜像、文档或日志。健康、就绪、迁移、SMTP受理、实际收件与生产 HTTPS 分层验收。

Go 进程平滑退出时停止接收新任务，通知实时客户端重连并完成有限时间内事务。任务租约过期后由其他 worker 或重启进程恢复。多实例扩展需要增加跨实例事件通知；通知只携带标识，客户端仍通过事件游标补齐数据。

### 11 2 建议初始性能目标

以下为需要压测验证的工程目标，不是已经测得的承载能力。参考起点为 4 vCPU、8 GB 应用节点，以及独立的 4 vCPU、8 GB PostgreSQL 节点和对象存储；网络、磁盘和数据库参数在压测报告中记录。

| 指标 | 建议测试条件与目标 |
| --- | --- |
| 实时连接 | 2000 个连接，含空闲与活跃连接，维持 60 分钟 |
| 消息写入 | 持续 100 条每秒，5 分钟 300 条每秒突发 |
| 接收确认延迟 | 测试环境消息提交确认 p95 不超过 500 毫秒，不含附件上传 |
| 实时事件延迟 | 同地域测试 p95 不超过 1 秒，排除客户端离线 |
| 分配冲突 | 100 个并发争抢同会话或最后一个名额，不超额 |
| 稳定性 | 断网、进程重启与任务重放后，已确认消息可恢复 |

租户、链接、访客、IP 和 AI 任务分别限流，限制单个租户占满连接、数据库与任务资源。测试达不到目标时先分析慢查询、锁竞争和消息队列积压，再调整容量或部署结构。

### 11 3 监控与恢复

记录活跃连接、消息确认延迟、补拉失败、分配等待、容量差异、数据库连接池、任务租约、outbox 积压、AI 成功率、发布失败率和租户额度。日志使用 request_id、tenant_id、conversation_id 等标识关联，默认不记录聊天正文、凭证和密钥。

建议生产 PostgreSQL 使用定期全量备份与持续 WAL 归档，初始恢复目标为 RPO 不超过 15 分钟、RTO 不超过 2 小时，必须通过恢复演练验证。对象存储版本与备份策略覆盖发布资源和附件引用。恢复环境核对租户总量、消息数量、模板版本和未完成任务，避免带 RLS 的备份查询意外遗漏租户。

## 12 测试与实施约束

### 12 1 自动化与集成测试

使用真实 PostgreSQL 和多个独立连接验证租户隔离、连接池切换、部分唯一约束、容量竞争和消息事务。单元测试覆盖算法与配置冲突；集成测试覆盖事务与权限；浏览器测试覆盖访客、客服、装修与 AI 完整链路。

重点故障注入包括提交成功但响应丢失、会话关闭后的成功消息重试、提交后进程退出、任务发送后未标完成、内部事件隐藏与访客补拉、乱序 worker 的队列公平性、转接确认与关闭竞态、AI 超时和迟到结果、资源上传成功但发布失败、两个并行发布的旧任务后完成、权限撤销时已有实时连接。各类失败后检查数据库最终状态，不只检查前端提示。

### 12 2 装修专项验收

逐个验证错误来源窗口、未知桥接方法、超长参数、越权会话、平台 Cookie、跨租户资源与代码包路径。代码页和预览页执行相同隔离。检查 PC 与手机键盘、长消息、附件、排队和离线；验证 AI 生成的租户模板能复制到两个页面独立编辑，并分别绑定链接。

平台模板升级或下架后，租户已发布页面继续有效。回滚不改变会话身份与消息序号。安全禁用时切到有效兜底并留审计，基础聊天页的存在和入口可达性应通过实际浏览器测试确认。

### 12 3 开发流程

开始产品代码前提交实施理解与计划并等待确认；开发前创建分支，完成后执行 git add、中文 git commit 和 git push，以用户最新工作规范为准。新源文件添加作用说明，新函数添加中文标准注释；安装依赖前检查国内镜像配置。

数据库迁移使用 PostgreSQL 语法及中文对象注释，先在测试库验证并准备回退方案。迁移与应用发布分别记录版本；不自动在生产执行未知来源 SQL。产品样式采用单色或自然色系，不使用蓝紫渐变。

### 12 4 推荐实施批次

按配套开发顺序与前端规范执行 D00 至 D10：工程后先完成官网和邮箱注册租户闭环，再完成成员、入口客户、聊天与分配，随后实现提醒自动回复、装修发布和租户 AI，最后完成运营与上线验收。网页首版包含上述能力，后续客户端复用接口并单独验收。

## 13 官网与邮箱身份实现

### 13 1 官网与 Ant Design

前端统一采用 Next.js App Router、React、TypeScript 与 Ant Design，使用官方 SSR registry 接入首屏样式。官网公开内容采用服务端或静态输出，交互组件按需要划分客户端边界。全局主题、表单、布局、按钮、反馈和响应式要求以开发顺序与前端规范为准，不能按页面引入不同管理 UI 库。

公开页面实现 metadata、canonical、Open Graph、robots 与 sitemap。sitemap 只列公开内容，租户工作台、认证页、访客聊天和含个资参数的链接设 noindex；认证数据与聊天不得进入公开缓存。生产 canonical 基于已配置官网域名，部署预览不误指向生产私有内容。SEO 依据见 T07、T09至T11。

### 13 2 邮件与验证码数据

增加 email_challenges、auth_sessions、member_invitations、email_delivery_records 和限流记录。验证码保存用途、规范化邮箱、摘要、到期、失败次数、已消费时间及重发世代，原码不出现在 API 响应、审计或普通日志。邮件任务若需要持久化待发内容，应加密保存敏感载荷，并设短期清理，不在公开任务详情中返回验证码。

验证码采用安全随机数生成，建议六位、5 分钟有效、60 秒重发间隔和最多 5 次错误尝试；按邮箱、可信来源 IP 与用途执行持久限流。新申请使同用途旧记录失效。消费时在 PostgreSQL 事务中锁定记录并检查世代、用途、到期、失败次数与消费状态，只允许成功一次。失败次数必须实际提交，不能随业务回滚而丢失。

密码使用 Argon2id 等适合密码的哈希，逐用户随机盐并保存参数版本；比较使用恒定时间路径。账户规范化邮箱有唯一约束，不能只在表单层查询重名。首次注册在同一事务内完成用户、新租户、所有者成员和默认资源；冲突时返回已有账户流程，避免分步写入孤立租户。

### 13 3 登录与邀请

邮箱验证码与密码登录共享身份和租户成员查询。管理登录创建可撤销的服务端会话，数据库只保存高熵会话令牌摘要，Cookie 使用 Secure、HttpOnly 与明确 SameSite 策略。密码重置、停用和退出其他设备撤销相应会话，WebSocket 在心跳或撤销事件中同步失效。

邀请在服务端绑定租户、邮箱、角色、接待范围、邀请人、期限和摘要。接受时验证当前邮箱匹配、邀请仍有效及邀请人权限，在事务内创建或复用用户并加入已有租户；不执行自主注册的新租户分支。公开注册不能选择 platform_admin。删除或降级管理员时锁定租户管理成员范围，保证至少一名有效管理员。

### 13 4 SMTP 参考与错误边界

参考 GoodHR 的 Mailer 接口、HTML 与纯文本模板、TLS、整体截止时间和结果分类，自行实现本产品邮件服务。使用本项目的 SMTP 配置名称；真实凭证只从服务端环境或受保护存储加载，经用户授权后才复用其他项目配置。

区分确定失败、可重试暂时失败、SMTP 已受理和结果不确定；DATA 完成后的断连不能直接判成未发送并无条件重试。验证码任务有申请记录与幂等键，过期或被新世代替代的任务不再发。注册事务提交后的欢迎通知使用 outbox，附加通知失败不回滚已经创建的账号。

生产缺少邮件配置时明确返回不可用并告警，不启用万能码或调试返回。测试使用本地假 SMTP 覆盖超时、TLS 拒绝和确认边界，真实邮箱收件另行验证。GoodHR 仅提供设计参考，不据其测试源码宣称本系统已发信成功。

## 14 接入参数与客户数据契约

### 14 1 统一初始化请求

初始化结构分为 entry_key、routing、profile、context、attributes 与 tracking。routing 包含 service_group_id、routing_pool_id、agent_id 和 agent_mode；profile 包含 display_name、phone、avatar_url 及可选外部身份线索；context 为本次访问 JSON；attributes 为已登记客户字段；tracking 为来源白名单。

GET 提供兼容的平铺字段，先标准解码一次再映射到同一结构。重复字段、类型冲突、非法 JSON 和受保护字段覆盖统一拒绝。建议 JSON 最大 16 KiB、深度 5、最多 100 键；GET 总参数建议 2 KiB，超过使用 POST 或 handoff_code。上限均由共享配置与 Schema 统一执行，代理请求上限需与应用一致。

客服业务组、分配池、服务空间和客户分类分别建模。增加 routing_pools、routing_pool_members、contact_categories、tag_categories、tags、contact_tags、contact_field_definitions、contact_field_values 和 contact_visits。分配池引用组或固定成员须有明确模式，同一成员在多个池仍共用一份租户接待容量。

### 14 2 路由与资料可信度

入口解析租户与服务空间后，先处理封禁和会话恢复，再解析被允许的动态路由。显式组与池取允许范围交集；指定客服必须属于最终范围。配置不合法与暂时无人可接待返回不同错误；只有白名单中明确允许的兜底才可扩展范围。规则版本与排除原因用于模拟路由和审计。

未验证 phone、external_user_id、uid 或昵称只保存展示线索，不能据其查询并返回旧身份历史。可信商户断言绑定应用命名空间、外部用户、入口、过期及重放标识；handoff_code 在受控事务中一次兑换，并绑定兑换幂等请求。商户签名密钥不得进入浏览器 SDK 或装修代码。

资料保留 provenance、verified_at、updated_by 和字段锁定。人工锁定、已验证商户、访客编辑与链接参数遵循需求覆盖顺序；0、false、null、未提供与清空分别处理。会话 context 保存快照，不能直接将任意键写入角色、身份状态、分配或系统列。

### 14 3 来源与外部资源

保存 URL 前去除验证码、签名、会话令牌、手机号等敏感查询项，日志不得打印完整初始化 URL。获取上级页面依赖宿主 SDK 明确传入，不跨来源读取父页。来源缺失不阻止咨询；统计同时保存首次、最近和会话创建来源，事件 ID 去重。

头像和远程素材优先受控上传；需要服务端代理抓取时限制 HTTPS、目标公网、重定向、DNS 变化、体积和超时，不能访问本地或内网资源。JSON 在 UI 中作为文本或已登记字段渲染，禁止不经校验插入 HTML。

### 14 4 黑名单与合并

增加独立 block_rules，记录范围、目标、原因、期限、状态和审计；封禁不删除消息。建立会话、发送、上传和实时订阅都检查规则，封禁后按政策关闭当前会话并幂等释放容量。平台封禁与租户封禁使用不同权限。

客户合并先锁定同租户主副客户和进行中会话，验证可信身份冲突，选择字段并迁移关联，保留别名与源会话。原消息作者、咨询来源和会话编号不重写。批量打标与分类变更接受幂等键和期望版本，异步批次保存逐项结果及权限快照，并在执行时重新鉴权。

## 15 消息交互提醒与运营细节

### 15 1 短期状态事件

正在输入是临时状态，不进入消息历史、不增加未读，也不保证可靠重放。按租户、会话、参与者、设备和接待版本保存短租约；建议每秒最多一次更新，3 秒停止、5 秒接收过期。多设备合并有效输入租约，单个标签页停止不能误清另一个标签页状态。服务端只收状态，不收未发送正文。

转接、关闭、撤权和断线清除旧范围；客户端忽略旧接待版本事件。进入会话、看到消息和正在输入不是同一行为，已读仍由实际可见范围上报。提醒默认基于新实时消息，补拉与重复事件不触发历史消息批量播报。

### 15 2 通知协调与语音

同一浏览器使用 BroadcastChannel 或支持的替代协调，只让一个有效标签页播放同事件提醒，领导页关闭后通过短租约接管。去重键包含租户、参与者与事件 ID，不把一次设备去重错误扩展成跨设备绝对只响一次。提醒偏好分别保存租户默认、用户设置和设备能力状态。

音效和 TTS 由可信运行层发起，自定义代码页只请求有限提醒能力。浏览器音频解锁、通知权限和麦克风授权由真实用户动作触发；拒绝时返回明确状态，保留站内提示。不能保证网页在关闭、冻结或锁屏后持续发声。浏览器边界依据见 T12 至 T14。

录音通过受支持的 MediaRecorder 类型与服务器实际内容校验，保存时长、类型、摘要及附件状态。权限授权与文件选择由可信父层处理，不向不可信代码页开放麦克风原始流或认证令牌。播放、暂停、取消和发送使用明确状态机，失败不提交残缺消息。

### 15 3 撤回引用与规则回复

撤回保留原消息身份和撤回事件，由服务端校验作者、时间窗口和当前权限；客户端替换为占位。引用只返回调用者可见的摘要，原文撤回或失权时清空引用预览。附件下载每次重新校验撤回和可见状态，已下载副本不在技术可追回范围内。

欢迎语、关键词回复、人工消息与内部备注带独立 sender_kind 或 source。延迟欢迎语使用持久任务，以会话和规则触发键幂等；执行前重查状态、规则版本和取消标记。关键词规则只处理访客新文字，明确匹配方式、优先级、冷却和最多一条命中，不能以自动回复再次触发自己。

### 15 4 检索导出与统计

会话列表导出和消息正文导出是不同任务，分别校验权限与保留范围。导出文件按租户、操作者与请求范围生成，下载短期授权并审计；CSV 对公式前缀进行安全转义。以 conversation_id 计咨询，转接独立统计，不采用时间间隔猜测会话边界。

定义访问人数、首次访客、发起咨询客户、会话、人工接待、首次人工回复和评价等独立指标。页面访问、打开聊天和发送消息是不同事件，系统欢迎语不计人工首响。统计使用一致的租户时区和去重键，批量导出与任务重试不能增加业务量。

### 15 5 新增接口与测试

新增公开注册、发送邮箱验证码、验证码登录、密码登录、密码重置、成员邀请接受、客服组、分配池、客户分类、标签、自定义字段、轨迹、黑名单、通知偏好和 typing 资源。认证写入与角色由服务端确定，所有管理路由沿用租户授权；WebSocket typing 与可靠消息事件分别定义 Schema。

集成测试补充 OTP 并发消费、注册回滚、邀请重放、最后管理员保护、JSON 特殊字符与超限、分组池交集、普通手机号历史越权、标签并发、封禁现有连接、输入状态过期、多页提醒去重、麦克风拒权、撤回引用和 CSV 权限。邮件与模型的测试替身仅验证逻辑，外部真实收件和生成另列证据。

## 16 套餐权益、坐席与真实开通

### 16 1 价格和订阅快照

出厂免费版 code=free、price_amount=0、currency=CNY、validity_days=0、seat_limit=2；0 天表示长期有效，对外主打永久免费基础客服。付费价格不预填虚构数据。plans 保存名称、说明、整数分金额、有效期、坐席、布尔功能字典、启用、公开和排序，官网 SSR 只读已启用公开版本。订阅和升级申请保存完整 plan_snapshot，后续套餐编辑只影响新申请或按已公开政策处理，不无痕改写已开通权益。

### 16 2 坐席预占与到期

可接待的成员占席，纯管理不占；有效待接受的可接待邀请预占。创建邀请、接受、启用、停用、移出、撤销和到期释放，在租户锁及同一事务中按 seats_used+seats_reserved 校验有效上限，检查不能只存在于前端。并发最后一席与同账号多租户独立计算需集成测试。

订阅 expires_at 为空表示长期有效；到期后 effective plan 返回当前免费版权益，原 subscription 保留历史及 expired 状态。限制超额新增业务，保留客户、消息、模板、附件和管理员查询及升级入口，不能按降级直接清理数据。

### 16 3 申请、收款、开通及审计

租户 POST upgrade-requests 仅创建 pending 申请，不扣款、不改变现有订阅。平台 activate 必须记录真实 payment_reference；付费快照价格大于0时要求 payment_confirmed=true。开通与申请状态切换、订阅快照和操作者审计在事务内执行，重复处理幂等。平台直接分配套餐执行相同实际收款检查，不能通过另一接口绕过。

### 16 4 独立记录与统计

记录与统计独立页面采用相同授权。访客按周期去重、访问次数单列，咨询按创建时间、消息按发送时间、客服按接待事实归属；系统自动消息不计人工首响。默认 Asia/Shanghai，自然日期结束日包含全天，内部以带时区半开区间查询。转接、多人接待和结束归属明确说明，数值通过固定样本复算。

导出分别处理会话元数据和消息正文，限量、异步任务、短期授权下载、审计和 CSV 公式转义不可省略；未完成后端能力不提供假导出。上线报告分开记录静态检查、真实 PostgreSQL、浏览器、SMTP收件、真实AI、Docker和生产域名证据。
