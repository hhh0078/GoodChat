# 客服工作台与链接改造

用户于2026年10月28日确认本轮改造，继续采用银白与钴蓝视觉，以高频接待操作和紧凑资料为重点。实施与验证证据另记在本轮验收记录，构建不代表真实业务验收。

## 接入链接与路由

每条链接独立配置自动分配或客服领取。`reception_mode` 为 `auto`、`manual` 或兼容旧入口的 `inherit`；旧入口继续使用分配池规则。创建咨询时保存入口快照，修改入口不悄悄改变历史咨询。自动队列跳过人工领取咨询，避免同池队头阻塞。手动领取仍核验组池、必备技能、上下班、忙闲、在线租约和容量，错误提示具体原因。

渠道以 `channel_tags` 保存多个标签；原 `channel_code` 保留为主渠道，避免多标签让统计重复计数。姓名后的列表标签和客户资料均展示来源快照。

分享窗口提供常用字段勾选、值输入、JSON示例和标准编码复制。中文字段姓名、手机号、头像、性别与原英文参数兼容；`sex=man`、`male`、`woman`、`female`、`unknown`等已知值统一为男、女、未知。`extra={"有无房产":"有","是否逾期":"无"}`及其他业务参数进入上下文，保留零、false和null；不冒充已核验身份。复访可更新本次业务资料，但旧访问重试不能覆盖较新的资料，也不改历史来源快照。

移除“允许参数选择接待范围”开关并默认开启。资料传递始终可用，路由目标仍受同租户、兼容组池和授权范围约束。JSON保留服务端大小、深度、字段数量限制。大资料应使用已有POST初始化接口，分享窗口明确提示链接长度边界。

## 客服工作台

- 咨询列表真实在线为绿色、离线红色，选中整行蓝色；颜色同时有文字或状态标识。访客在线由服务端探活租约决定，不用会话状态推断。
- 输入区左侧展示公共与个人快捷回复，右侧为较矮的消息输入；普通客服只维护个人话术，公共话术由管理员维护。双击直接发送，同时保留按钮和键盘操作。
- 内部备注从聊天记录和输入模式中移除，在右侧按客户累计为多条记录，显示操作人和时间，跨咨询保留；旧内部消息及附件仍可在备注中读取。读写均要求当前客户授权，不凭旧接待关系继续访问后续资料。
- `GET /tenant/contacts/{id}/notes` 使用 `before`、`before_id` 和 `limit` 联合分页；`POST` 使用 `content`、稳定 `client_note_id` 幂等写入。同编号不同内容返回冲突。
- 客户资料紧凑排列姓名、电话、次要建档时间、渠道和逐行额外参数；空备注隐藏，访问记录可折叠。上班、忙碌、下班分别绿、黄、红。工作端不显示租户切换入口。
- 消息提醒默认接收，音量控件替代启停按钮；零音量图标红色，系统通知单独可选。声音遵循浏览器首次交互解锁规则。
- 文字发送有短运动反馈，但发送中、失败和服务端确认分别显示；语音使用统一紧凑播放卡片，保留鉴权下载与单一播放。

## 网页消息可靠性

详细设计、公开产品依据、诊断入口及浏览器限制见[实时连接与消息恢复](实时连接与消息恢复.md)。消息先在数据库事务中保存，通过WS提示变化，HTTP签名游标补齐。首次历史快照和同步游标在同一锁定范围内读取，避免初始化间隙遗漏；消息重试复用原编号。

发送前将未确认消息保存在按身份、租户、咨询隔离的同标签会话存储中，不保存票据或登录令牌。刷新后显示待确认记录，由用户重试；服务端确认或补拉看到同编号后清除。存储不可用时明确提示并保留草稿。该暂存不能代替服务器持久化，也不承诺关闭标签后保留尚未提交的消息。

Worker减轻主界面阻塞，服务端协议探活维持在线租约；冻结或系统睡眠仍可能断开。验收重点为准确显示断开、恢复后补齐和不重复发送，不宣称网页永久在线。

## 服务统计

默认租户当地当天，选择日期按租户日历解释。单日返回小时趋势，跨日使用每日数据；原始明细表仍保留。曲线控制点不越过相邻样本计数范围，避免平滑产生负值或虚构尖峰。夏令时单日支持23或25个小时，用时间戳区分回拨重复小时。

## 开发与验收顺序

先完成兼容迁移与路由/权限接口，再接参数、备注和工作台交互，最后集中验证消息故障恢复及桌面/手机布局。新增迁移为016和017，数据库字段均有中文注释。

验证覆盖参数兼容、混合自动/领取、并发容量、内部备注幂等分页和撤权、真实WS探活/半开/重连、原子快照、待确认消息重试、小时统计与夏令时，以及浏览器实际发送与断网恢复。测试内容使用明确的“演示数据”标识。网页自动化无法代替真实笔记本合盖、长期后台、设备与生产环境验收。
