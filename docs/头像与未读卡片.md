# 头像与未读卡片

日期：2026年10月28日。分支：`codex/avatars-unread-cards`。此前工作台、链接与实时连接改造见[工作台验收](客服工作台改造验收.md)和[消息恢复](实时连接与消息恢复.md)。

## 咨询列表

每个客户卡片都有圆角和独立间距；选中使用浅蓝底、蓝色边框与深色文字。第二行只显示在线或离线状态及手机号，渠道标签跟随姓名。公开访客消息的未读数量以红底白字数字显示，超过99显示99+。

未读数由服务器按当前客服自己的`read_cursors`计算，统计未撤回的公开访客消息。内部备注、客服自己发送、系统消息和原编号重复发送不增加未读。其他管理员或客服查看不能替本人清零。旁观管理员的个人已读不对访客广播成接待客服已读。

点击卡片不会直接清零。聊天页面在前台可见、消息加载完成、真实滚动到底连续两帧后才提交已读；服务端确认后刷新数字，失败会继续重试。向上查看历史和浏览器后台不提交最新消息已读。

列表按最近公开消息的真实保存时间倒序；没有消息的咨询使用创建时间。已读、心跳和内部备注不改变位置。收到新消息后经实时通知刷新，连接恢复及兜底轮询也重新读取列表，因此刷新页面仍能还原未读与位置。修改排序不改变已有筛选或成员可见范围。

## 头像规则

平台库共50张独立头像：职业人物20张、卡通人物20张、萌趣插画10张。素材与生成记录位于`frontend/public/images/avatars/`及`docs/designs/2026-10-28-avatars/`。生产版本统一通过`backend/cmd/avatar-assets`调用上传同款图片规范化流程，最长边256像素、单张不超过256KiB。

租户管理员在设置的“访客头像池”中多选平台头像并上传自有图片，保存后构成本租户的随机池；空池表示使用全部平台默认头像。当前成员可以设置自己的固定客服头像，保存位置为本租户会员，避免影响其在其他租户中的身份。

没有明确头像的新客户从租户池随机选择一次并保存，刷新或重新显示不反复更换。已有头像与人工锁定头像保留。中文头像参数或兼容英文参数传入的有效HTTPS地址优先。旧空头像由迁移补全，首次回访也会原子补选，防止并发访问多次替换。

上传支持PNG、JPEG、GIF、WebP，限制5MiB、400万像素与4096边长，实际解码并重编码为PNG，不保存源文件元数据。GIF取解码首帧。解码槽只覆盖CPU处理阶段，慢传不会占满其他租户的解码槽。头像是公开展示资源，上传入口对此有明确提示。

## 接口与隔离

| 接口 | 规则 |
| --- | --- |
| `GET /tenant/avatar-assets` | 平台库及当前租户上传素材 |
| `POST /tenant/avatar-assets` | 当前有效成员上传，multipart字段`file` |
| `GET/PATCH /tenant/avatar-pool` | 读取池；管理员提交`avatar_refs`数组，空数组恢复默认 |
| `GET/PATCH /agent/avatar` | 当前会员提交单个`avatar_ref`，空字符串恢复首字头像 |
| `GET /avatar-assets/{id}` | 随机UUID只返回已重编码PNG字节与缓存头，不返回租户、上传者或客户资料 |

所有写接口从认证上下文取得租户。普通成员不能修改租户池，不能引用其他租户上传资源。数据库迁移018保存上传素材及会员头像；019维护公开消息活动与旧空头像补全，表及字段均有中文注释。

原生聊天页直接展示受控头像。隔离装修页通过新增`GoodChat.getAvatar(message_id)`读取当前公开且未撤回消息的受控头像Blob，再在沙箱创建本来源地址；父层只允许固定平台图片和本平台头像UUID路径，拒绝任意网址、附件路径、跨会话或已撤回消息。图片读取不携带身份凭证，不放宽装修CSP。外部HTTPS头像在隔离页面中保持首字回退；原生页面可显示。自定义旧模板可以通过该SDK能力自行加入头像，新建代码初稿及标准组件已接入。
