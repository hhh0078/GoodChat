# 运行监控与成员统计

## 资源监控与范围

`backend/internal/monitoring/`每秒采样，保留本进程最近120个样本，页面每5秒读取。根据`/proc/self/cgroup`与`mountinfo`先定位当前进程的cgroup v2子组，再使用对应子组的`cpu.stat`、`cpu.max`、`cpuset.cpus.effective`、`memory.current`与`memory.max`。不会直接将系统挂载根当作应用；只有识别到容器且私有归属为`/`时才接受其根控制组。归属、挂载或根应用边界无法确认时退回Go进程并说明原因。

同控制组内的进程一起计量，范围可能包含同服务的多个进程。CPU使用率按累计微秒差分除以实际采样时长与有效核数计算；ticker只负责触发，时间取实际读取时刻，避免暂停恢复后旧计划时间导致虚假尖峰。

未知资源使用`null`；首次没有CPU差分时不显示假零。没有独立内存上限读数时不计算使用率，环境可见总内存单独展示。Go堆只作为Go运行时指标，不冒充整个应用或物理宿主机内存。范围解释依据[Linux控制组官方文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)和[Go运行时指标文档](https://pkg.go.dev/runtime/metrics)。

实时计数从聊天服务连接表取得：连接数按Socket计算，客服按账号去重，访客按租户及客户身份去重，同一身份多个标签页不会多算人。它描述当前单实例真实连接，不能当作所有已登录账号或整个平台多实例总数。

接待余量来自在线、上班且非忙碌成员的真实容量与占用。已满容量的成员不计为仍可接待。此项属于业务接待名额，与服务器可承载在线人数分开展示。

## 压测基线与估算

没有记录时显示`uncalibrated`，不编造人数。总管理员可记录已完成测试的同时在线人数、实际测试日期、场景说明与安全系数；默认系数0.7，允许0.3～0.9。系统不会自动验证管理员录入的测试。接口字段：

```json
{"tested_people":1000,"safety_factor":0.7,"test_date":"2026-10-29","notes":"填写实际完成的业务场景、消息频率、媒体和结果"}
```

上述内容只是接口格式示例，不代表已完成1000人压测。

安全容量为`floor(实测人数 × 安全系数)`，额外人数为`max(0, 安全容量 - 当前去重实时在线人数)`，不外推到未经测试的更高并发。服务端记录实际监控范围、有效CPU与内存规格指纹，不接受客户端提供的指纹或资源规格。没有独立内存配额时，将环境可见内存纳入指纹。

规格发生变化时显示`stale`且余量为空，必须在当前部署重新压测后记录。负载用量变化不会改变规格指纹。删除基线恢复未校准，适用于错误记录和明确标记的演示记录。应用代码、业务消息频率和媒体比例变化也会影响承载，应重新做业务压测；基线公式不保证所有业务混合负载均有相同表现。

迁移024保存单例压测记录及录入人，只有总管理员API可以修改。记录不在内存中，重启后仍可读取；最近两分钟资源曲线会重新积累。

## 在线采集

`backend/internal/presence.Renew`由已通过权限复核的WS探活调用，所有租户成员都能采集，包括仅管理的成员。只有可接待成员续接待运行租约，探活不改变上班或忙碌意图。

同一租户成员的探活先取得事务级成员锁，将45秒内的重叠标签合并到同一区间。断开后最多保留45秒租约。在线时长按照查询范围与当前时刻裁剪，不把未来租约、其他租户或启用前没有采集的时间计入。团队列表每15秒刷新租约在线状态。

迁移021只依赖身份表，适用于身份测试fixture；保存区间、最近探活与到期时间并使用强制租户RLS。不存在历史数据的日期显示0分钟，并提示从启用采集后开始记录。

## 成员统计口径

- 接待人次：本期实际确认接待的去重咨询，每个成员分别计自己的接待。转接双方各有自己的工作量。
- 首响：本期接单的每段接待，从确认时刻到本人首条未撤回公开人工回复，排除排队、系统和内部消息；未回复段不进入平均值，显示样本数。
- 平均回复：本期每条有效公开人工回复，按`event_seq`找到前一条公开人工回复之后最早的访客问题，每个等待段只配对一次；连续补充问题不重复计样本。接单前已有等待从本人接单时刻起计，无待答问题的主动消息不计入。
- 结束数：本期结束且最终接待人为本成员的咨询。
- 公开发送消息：本期人工公开消息，另列已撤回数量，内部消息不混入。
- 评价：按本期创建评价的最新评分，归于`final_agent_id`固化的最终接待人。无评价显示空值，4～5星视为满意。
- 当前在线、接待占用和容量是读取时的实时快照，与历史筛选日期独立。

首响和评价的总体均值按真实样本数加权，不直接平均每个成员的平均值。被停用或移出的成员保留历史统计并显示状态。前端缓存绑定租户与完整日期范围；切换日期失败不会把旧日期数据标成新日期，临时失败只保留同一范围缓存，失权清除缓存。成员统计、监控与接入统计轮询在各自生命周期内串行，切换范围或卸载时取消旧请求。

## 接入管理

默认按租户时区今天统计，页面每30秒更新。UV为实际访问链接中的平台客户身份去重，PV为已经按`visit_id`去重的访问记录数；手机号相同不能证明是同一个客户。跨链接复访按实际`access_link_id`统计，不能被旧咨询的创建入口吞掉。

新建、结束咨询按咨询创建入口归属。当前排队和接待数是当前快照，不限定咨询一定今天创建。迁移023为按日期汇总和接待段查询增加索引，同时给客户列表复用联系人历史索引。

## 实际验证

14项后端针对性测试及`-race`通过：真实Cookie权限与基线CRUD、临时目录模拟的systemd子组/容器根/子树挂载与未知范围拒绝、控制组CPU/内存和未知值、公式封顶/规格失效、连接身份去重、多标签在线合并与仅管理成员、真实接待容量、转接后首响与两段等待平均回复、评价最终归属、跨入口访问及租户午夜边界。3项前端状态测试验证日期和租户范围隔离、慢请求串行、失败恢复及取消后不再执行；TypeScript检查通过。

测试使用隔离随机schema及本地SMTP捕获身份验证码，没有外发业务邮件。页面浏览器与最终容器验收由主任务另行记录；这些测试不代表已完成当前部署真实并发压测。
