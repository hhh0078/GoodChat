# 2026-11-27 单工作台与官方客服归并

## 问题与最终行为

同一账号原有两个有效租户，登录只进入最早的有效身份，另一租户的转人工提醒无法在当前工作台找到。现在账号只允许一个有效工作台，租户内只有一个默认服务空间，不新增租户或空间切换。GoodHR和GoodChat通过原有公开接入链接区分，单个链接可明确选择独立机器人配置。

- 注册、邀请发起/接受、平台代开和历史成员重新启用统一检查账号有效工作台，数据库唯一索引兜底并发。
- 服务空间唯一并必须默认；接入接口拒绝额外空间。租户隔离、成员角色和会话权限保留。
- 同成员的两套机器人保留独立ID、提示词、模型继承、知识授权、时段和预算。本人可选择编辑/调试，其他成员不可借ID越权。
- 转人工邮件使用校验过的会话UUID生成站内深链；登录保留完整返回地址。旧或已结束会话通过原鉴权单条接口打开，不依赖默认最近三日列表。
- 原访客缓存只在同源同接入链接范围恢复旧空间键，服务端仍验证原凭证，绝不跨入口共享身份。

## 数据迁移保护

运营迁移在独立维护窗口执行：先做数据库备份并在现有PostgreSQL的隔离库恢复演练，再停写、最新备份、事务归并、候选镜像迁移和检查、正式切换。自动部署仍不增加备份行为。

原公开入口key、访客会话凭据、联系人的ID、聊天/消息/知识/机器人ID保持。迁移事务对核心业务记录排除必要身份映射字段后逐条比较JSON内容；检查全部外键后恢复原可延迟属性和资金流水不可变触发器。来源钱包原值记入审计后清零，两钱包余额及预留总额守恒。原租户和成员关系归档停用，不删除历史身份。

来源欢迎语转换为来源接入链接的规则，避免污染另一入口。两套AI内容不合并成一个提示词，也不扩大机器人知识授权。源通知幂等键切换目标租户前缀，避免扫描器重复发送历史提醒。
