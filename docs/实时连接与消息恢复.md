# 实时连接与消息恢复

## 职责与代码位置

- `frontend/src/lib/realtime/client.ts`：身份连接状态机、ready等待、心跳超时、退避重连、恢复与安全诊断。
- `frontend/src/lib/realtime/use-realtime.ts`：同一页面内同身份共享一条WebSocket；客服列表与会话不再重复连接。管理网络、前台恢复、页面恢复及资源释放。
- `frontend/src/lib/realtime/scheduler.worker.ts`：Worker中的检查时钟。浏览器不支持、加载失败或策略拒绝时自动退回普通时钟。
- `frontend/src/lib/realtime/sync-pump.ts`：业务补拉串行器；补拉进行中再次收到提示时保留唤醒，完成后再扫描。
- `frontend/src/features/chat/use-chat.ts`：快照、签名事件游标、重复事件过滤、历史记录和原有HTTP幂等发送。
- `backend/internal/chat/realtime.go`、`realtime_probe.go`：一次性票据、权限复核、连接隔离、服务端协议Ping/Pong、在线租约与日志。

这是一组独立维护的代码模块，不额外部署WebSocket微服务，也不需要客服安装后台程序。

## 消息事实与连接状态

WebSocket是及时提醒通道，数据库中的消息和事件才是事实来源。收到事件提示、连接恢复或兜底轮询时，客户端通过HTTP读取持久事件，并且只用服务端签名游标推进位置。不能用客户端猜测的序号跳过未扫描的事件。

发送仍经HTTP接口，并保留同一个`client_message_id`处理超时重试。只有服务器确认持久化后才加入成功消息列表。已有失败消息和草稿保存逻辑继续生效；失败与“服务器可能已收到但响应中断”都不能换编号重新发送。

普通聊天页和已发布装修页共用 `useChat.send` 的发送前暂存：完整消息体按租户、发送身份和咨询隔离，写入当前标签页的 `sessionStorage`，不保存认证令牌。HTTP确认或持久消息补拉见到原编号后清理；刷新后的未确认记录只供手动重试，不自动发送，也不生成新编号。

装修页使用可信父层 `UnconfirmedMessages` 显示恢复入口：消息快照加载完成且存在未确认条目时，逐条显示文字或附件说明、暂存错误及重试按钮。重试直接使用原完整消息体。暂存内容、恢复状态与错误不会加入装修 `state()` 或通过 `MessageChannel` 发送给不可信 iframe；既有精确来源、握手和附件权限边界保持有效。

客户端合并消息按稳定编号去重，字符串序号按BigInt比较。初始最近50条消息与`sync_cursor`在同一数据库事务内受会话共享行锁保护，发送和撤回的行锁与其串行，因此快照水位之后发生的消息由事件补拉覆盖，不需要从零重放全部旧历史。只有初始非分页响应提供`sync_cursor`，加载更早历史不能倒退实时恢复位置。游标过期或身份范围变化时，立即重建快照、清理事件去重位置并从新水位继续扫描。补拉期间收到的新提示会再次触发扫描，不会因为“已有请求正在运行”而被吞掉。

状态依次为：连接中、恢复中、已连接；网络失败为断开/重连，身份撤销为身份失效。TCP握手或`onopen`不代表数据已恢复；收到`ready`并且注册的恢复回调完成后才显示绿色成功状态；选中会话额外等待持久消息补拉完成。咨询列表仍由列表资源刷新和HTTP轮询维护，不将触发一次刷新等同于列表请求已完成。

## 保活、后台与睡眠恢复

服务器每15秒发协议Ping，10秒内要求Pong；成功后重新检查租户、成员或访客权限并续租45秒。浏览器可以由网络实现回复协议Pong，不必依赖页面JavaScript定时器按时执行。服务器同时发安全心跳回执；客户端超过45秒没有服务器帧时视为失效连接并重连。

连接建立后立即检查身份并续租，不必等待第一次15秒心跳。客服的`available`和`busy`是明确的业务意图，心跳与重连只更新在线租约，不能把下班或忙碌自动改成上班。

Worker减轻界面繁忙造成的调度影响，但它是浏览器线程，不是独立操作系统进程。系统睡眠、浏览器冻结或丢弃标签页时，不能承诺WebSocket不断线。恢复网络、返回前台、页面恢复时会立即核验旧连接或重连，并补拉持久消息。重连使用有上限的指数退避和随机抖动；401/403或策略拒绝停止自动重试，避免无效请求风暴。

同一身份的连接只在当前页面内复用；多个标签页各自维护连接。关闭页面后不提供Web Push或桌面后台提醒。当前服务为单实例实时推送；未来横向扩容需补共享事件分发，不能仅扩容进程就认定所有实例都能即时收到outbox通知。HTTP持久事件补拉仍是恢复兜底。

## 排错

工作台实时状态可查看最近40条诊断，包含阶段、固定原因、重试次数、重试等待。后台日志使用`realtime_connection`记录连接ID、握手请求编号、租户、身份类型、打开/关闭阶段与关闭码。

诊断不记录一次性票据、认证凭证、完整URL、手机号或聊天正文。需要关联错误时使用请求编号；不要把浏览器网络面板中的完整WS URL复制进公开日志。

服务端事件游标使用运行配置`AuthSecret`派生的专用密钥。同配置重启或切换实例不再因为随机启动密钥而失效；轮换密钥后会自动重建快照。

## 验证范围

自动测试覆盖：握手不提前标绿、恢复完成后成功、半开超时、旧连接回调隔离、换票据、权限失效停止重连、断网及长时间恢复、补拉并发唤醒和失败后的继续恢复。真实WebSocket测试覆盖没有应用心跳仍能续租、缺失Pong超时、权限撤销。真实数据库集成测试核验一次性票据、立即续租、访客在线以及上下班/忙碌意图保留。

自动测试不等于macOS合盖、系统睡眠或所有浏览器后台策略验收。发布前需在目标Chrome/Safari执行：后台超过5分钟、最小化、冻结/丢弃、合盖唤醒、Wi-Fi切换、服务器重启，再检查两端消息、未读、在线租约及失败消息重试。Chrome可用`chrome://discards`主动冻结/丢弃标签页。

## 公开实践依据

本实现参考下列公开文档中的连接状态分类、完成同步后操作、会话恢复和复用客户端原则；不复制第三方凭证协议，也不引入第三方客服SDK。

- [Twilio SDK clients best practices](https://www.twilio.com/docs/conversations-classic/best-practices-sdk-clients)：区分初始化和同步，等待同步完成再执行依赖数据的操作。
- [Twilio error handling and diagnostics](https://www.twilio.com/docs/conversations-classic/error-handling-diagnostics)：监控连接状态与连接错误，区分身份拒绝和网络恢复。
- [Zendesk Chat Conversations API](https://developer.zendesk.com/api-reference/live-chat/chat-conversations-api/conversations-api/)：异常断开后恢复会话。GoodChat票据只能消费一次，因此重连必须申请新票据，不能重复使用旧WS URL。该Zendesk旧接口文档只作为历史设计参考，非新增集成建议。
- [Stream官方客户端源码](https://github.com/GetStream/stream-chat-js/blob/master/src/client.ts)：单客户端连接及重连后恢复活动频道状态。
- [Chrome Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)：冻结、丢弃、恢复和测试方式。
- [MDN Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)：Worker线程与页面通信边界。
- [MDN Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：页面可见性与后台策略，部分实时连接有豁免但不能替代恢复逻辑。
