# 在线客服 SaaS 需求文档

网页首版与后续客服客户端规划

版本 1.2　日期 2026年10月26日　负责人 邓云川

本产品品牌为 GoodChat，默认以永久免费基础版、2 个客服坐席起步。本产品面向需要在线接待客户的商户，提供多租户管理、多个接入链接、统一客服工作台和可定制的访客聊天页面。首版交付网页产品，访客页面适配电脑与手机；租户可以自行用 AI 创建设计，保存为本租户模板，预览后发布到接入链接。本文用于产品评审、开发拆解与功能验收，技术实现与约束见配套技术文档。

### 1 2 网页首版边界

首版包含完整的租户开通、客服配置、链接接入、分配排队、聊天、装修、模板、AI 生成和发布回滚闭环。平台管理员端与租户端以电脑网页为主要操作环境；客服工作台提供电脑完整界面和手机网页的基础接待能力。访客页以电脑与手机网页同等可用为验收要求。

首版覆盖独立聊天链接与网站嵌入方式。后续接入小程序、App、微信公众号、微信客服和企业微信等入口；外部渠道需要分别完成授权与能力验证，其支持范围按实际接入结果发布。macOS、Windows、Android 属于后续客服端，不作为网页首版已经交付的能力。iOS 原生客服端未列入当前确定范围。

AI 装修是首版能力；AI 自动接待、知识库问答和机器人转人工属于另外的产品功能，另行规划。首版包含套餐权益和人工开通续期；在线支付、自动续费与发票流程在支付渠道确认后单独扩展。

## 2 角色权限与工作端

### 2 1 平台管理员端

平台可直接开通租户，填写租户名称、初始所有者邮箱、称呼、时区和是否接待，事务保存租户及激活邀请。受邀人验证指定邮箱后成为所有者，不发送明文密码；稳定幂等键保证失败重试不重复建租户。邮件失败不隐瞒已保存资源，提供针对原租户的邀请重发及冷却。

平台管理员管理租户、套餐权益、平台模板、AI 服务配置与系统运行。支持租户开通、禁用、续期、额度调整、账号恢复和操作审计。停用租户时阻止新接入与新增业务写入，向当前连接推送明确状态；历史数据按平台保留策略保留，不自动删除。

平台模板后台支持新建、上传代码资源、可视化编辑、AI 辅助创建、分类、封面、排序、预览、发布、下架与版本维护。平台 AI 配置包含供应商、模型、可用性、默认限额和用量统计，密钥只保存在服务端。

查看租户聊天正文、导出客户信息和代租户操作属于单独的支持权限，需要注明目的、目标租户并记录审计。普通平台运维视图以状态和统计为主。

### 2 2 租户端

租户管理员维护组织资料、成员、角色权限、客服组、技能、营业时间、服务空间和接入链接。能够配置分配规则、接待容量、排队与超时处理、快捷回复、欢迎语及历史可见范围。

装修工作台提供基础设置、可视化编辑器、代码编辑器、AI 创作入口、我的模板、平台模板、素材库、预览和发布管理。租户能够查看本租户会话、访客、留言、服务统计、套餐权益与 AI 用量。

### 2 3 客服端

客服可以登录、切换上班与接待状态、查看待接与当前会话、发送文字图片文件、维护备注标签、使用快捷回复、转接与结束会话。管理权限和接待权限分别授权，租户管理员兼任客服时也适用接待容量规则。

客服仅可访问自己当前接待及明确授权的历史、技能组或协作会话。管理者查看全租户会话需要额外权限。客服退出某会话或权限被撤销后，已打开的页面与实时连接同步失去相应访问能力。

### 2 5 官网与搜索引擎收录

官网突出基础版永久免费、包含 2 个客服坐席；扩展坐席与功能的价格按已发布套餐展示，不承诺每次咨询必然获得响应。产品提供独立官网，包含首页、功能介绍、行业方案、套餐说明、接入文档、常见问题、登录注册入口、隐私政策与服务条款。页面展示真实功能范围和服务方式；未确认的价格、客户数、承载量和服务承诺不作为宣传事实。官网需要电脑与手机适配，主要介绍内容无需执行 JavaScript 也能从 HTML 读取。

公开页面分别配置标题、描述、主标题、规范地址、分享图和语义化结构；提供 robots 与 sitemap，只收录公开内容。登录、找回密码、管理端、客服工作台、客户聊天链接和含客户资料的个性化入口不进入 sitemap，并设置 noindex。页面参数不产生大量可索引重复地址，旧公开地址变更时提供规范跳转。域名、公司主体和联系资料通过平台配置维护。

### 2 6 邮箱注册与自动创建租户

官网支持通过邮箱注册。用户填写邮箱、邮箱验证码、租户名称并设置密码；可在注册前查看条款。发送验证码时展示倒计时和发送结果，支持修改邮箱后重新获取。邮箱验证通过后，在一个事务内创建登录账号、新租户、所有者管理员成员关系和默认服务资源，然后进入租户初始化向导。

首次自主注册的用户自动成为自己新租户的所有者兼租户管理员，不需要平台人工授予。公开注册请求中的角色、租户ID或客服ID不能把用户加入其他租户，也不能授予平台管理员。相同邮箱并发注册、重复点击和网络重试不会创建多家重复租户。已注册邮箱进入登录或密码找回流程，不因再次登录新建组织。

初始向导建议包括租户名称和品牌资料、默认服务空间、客服分组、添加成员、接待时间、创建首个接入链接和选择装修模板。可以跳过非必需步骤稍后继续，但默认资源必须能让管理员以客服身份完成自己的测试咨询。管理员是否参与接待通过独立开关管理，具备管理权限不自动占用一个活跃接待名额。

### 2 7 邮箱登录密码与会话

首版支持邮箱验证码登录和邮箱密码登录，提供忘记密码、设置新密码、退出当前设备和退出其他设备。建议密码为 8 至 128 位，允许粘贴与密码管理器；服务端以现代密码哈希保存，不能明文保存或通过邮件发送原密码。找回流程验证邮箱后设置新密码，并按策略撤销已有登录会话。

验证码按邮箱、用途和申请记录绑定，建议有效期 5 分钟、同用途重发间隔 60 秒、每条最多失败 5 次；服务端限制邮箱、IP和用途维度的频率，页面倒计时不替代服务端限流。成功验证码原子消费一次，重发后旧码失效；注册、登录、重置密码和邀请不能互相混用。生产环境禁止万能验证码、接口返回验证码或未配置SMTP时假装发送成功。

发送状态分别表示正在处理、邮件服务器已受理、明确失败或结果待核对；已受理不承诺已进入收件箱。用户可核对邮箱、查看垃圾箱提示并在限流允许后重发。登录错误采用一致的安全提示；风控需要额外验证时说明操作原因，不无限循环。

### 2 8 添加租户管理员与客服

租户管理员可以通过邮箱邀请或创建待激活成员，角色可选租户管理员、客服以及后续扩展的自定义角色。表单填写邮箱、显示名称、角色、所属客服组、可用分配池、技能和接待上限；管理员角色与接待资格分别设置。平台管理员也可在授权范围内为既有租户添加管理员。

邀请邮件只包含指定租户的加入入口和有效期，不包含初始密码。受邀人验证匹配邮箱后加入该租户；新邮箱可以建立账号但不再自动创建第二个租户，已有账号保留其他租户关系并选择当前工作租户。建议邀请 7 天有效，可撤销、重发和查看待接受状态；新邀请替换旧凭证，重复接受保持幂等。

邀请角色和权限由服务端保存，受邀链接不能修改自己成为更高权限。租户管理员不能创建平台管理员，普通客服不能邀请管理员。至少保留一名有效的租户管理员；停用、降级或移除最后一名管理员时阻止操作并说明原因。所有者移交需要现有所有者重新验证并指定已激活管理员。

成员支持启用、停用、移出、分组调整、权限修改和接待状态查看。停用后撤销登录会话、停止新增分配，处理其当前接待与未完成转接；历史消息仍保留真实作者与统计归属。重新启用不恢复已撤销邀请或自动抢回原会话。

### 2 9 前端统一与本章验收

官网及三端采用 React、Next.js、TypeScript 与 Ant Design；统一主题、组件、布局、表单、错误反馈和权限呈现，细则见开发顺序与前端规范。访客装修可在受控范围内自定义，后台工作端始终遵循统一规范。

本章验收包含官网无JavaScript核心内容、SEO字段和sitemap、验证码限流过期重放、SMTP失败与结果不确定、并发注册只建一个租户、公开注册不能提权、邀请新旧邮箱加入原租户、邀请篡改和过期、最后管理员保护、密码重置撤销登录及多租户切换。测试邮件和真实收件分开记录，不把本地测试验证码当真实邮件送达。

## 3 多链接与访客接入

### 3 1 链接配置

每个链接拥有不可猜测的公开标识，支持名称、说明、所属服务空间、启停、有效期、来源标签和二维码。租户可以为售前、售后、广告投放、门店或指定客服建立不同链接。后台提供复制链接、查看二维码、访问预览、接入说明与统计入口。

链接绑定接待组、分配规则、营业时间、指定客服模式、装修页面和发布版本。可以跟随某页面的当前发布版本，也可以固定到指定发布版本。新建链接默认使用租户默认页面；页面尚未发布时使用平台基础聊天界面。

例如，同一租户建立售前链接与售后链接：售前使用产品展示装修和销售组，售后使用服务说明装修和售后组。电脑和手机访问同一个链接时，显示对应的响应式布局。

链接参数可以携带来源、商品或订单上下文；客户真实身份与权限由服务端验证。公开链接和公开参数不能直接授予读取历史聊天的权限。修改链接名称、归属或规则只影响后续行为，既有会话保留创建时的来源与规则快照。

### 3 2 访问流程

1. 访客打开链接，系统检查租户与链接状态，展示已发布页面和服务状态。
2. 系统建立当前租户内的访客身份；进入页面本身不重复创建会话。
3. 访客点击开始咨询或首次发送消息时，服务端恢复可继续的会话，或者创建新的咨询。
4. 营业中按规则分配或排队；营业时间外按配置提供继续等待或留言入口。
5. 客服接待后显示接待状态，访客可发送消息、上传附件并查看允许的历史。
6. 会话结束后显示评价入口；再次咨询创建新的会话编号。

链接失效、租户停用、访问过快和服务暂不可用时，页面给出明确提示及允许的替代入口。切换链接配置不能使正在咨询的访客突然丢失会话。

### 3 3 身份与跨链接续接

匿名访客通过当前租户下的浏览器身份继续访问。清理浏览器数据、无痕窗口或更换设备可能产生新身份；IP 和浏览器指纹不作为读取历史的凭证。商户登录客户可以通过签名身份接口关联到其业务账号，以支持可信的跨设备续接。

建议默认按租户、服务空间和访客查找未结束会话。同一访客重复刷新、打开多个标签页或从同一服务空间的其他链接进入时，复用当前会话。不同服务空间可以各自存在一个进行中会话。新入口记录为访问轨迹，原始会话来源保持不变，不自动触发转接。

恢复既有会话优先于新链接的指定客服、技能与营业规则；这些规则用于新建或明确重分配。若访客进入的链接与当前接待范围不一致，页面提示继续原会话，并提供显式结束原会话后按新入口重新咨询的操作，不同时重复排队。

客户、渠道身份、会话与接待客服分别保存。同一客户重新分到同一客服，也必须保留新旧会话边界。租户可以配置访客是否展示本人旧会话；客服端是否能查看旧会话由权限单独控制。隐藏历史只影响可见范围，不改变保存和统计规则。

### 3 4 接入参数字典

以下是新系统的统一协议命名，不代表 CRMChat 已完整实现。后台提供链接生成器：选择入口、接待范围、访客资料来源与业务上下文后，生成可复制链接、二维码、嵌入代码和调用示例。电脑与手机使用同一套参数及服务端规则，设备类型只影响界面适配。

| 参数 | 含义与规则 |
| --- | --- |
| entry_key | 必需的公开入口标识，通常放在路径中；由服务端解析所属租户、服务空间和允许的接待范围 |
| service_group_id | 客服业务组标识；仅可选择本入口允许的组，不能表示客户分类 |
| routing_pool_id | 分配池标识；确定候选客服集合与分配策略，可由入口固定或在白名单中动态选择 |
| agent_id | 指定客服的租户成员标识；不是登录账号、客户编号或其他租户客服编号 |
| agent_mode | 指定客服的 strict 严格模式或 prefer 优先模式；默认采用入口设置，公开参数不得擅自放宽 |
| channel_code | 租户内来源渠道编码，如广告投放、官网或业务 App；不等于微信等外部渠道的授权凭证 |
| external_user_id | 商户业务用户标识；未经商户服务端签名验证时仅为线索，不用于恢复历史身份 |
| display_name | 访客展示姓名或昵称；默认最多 80 个字符，不承载实名认证含义 |
| phone | 访客联系电话；保留原始输入、规范化值及验证状态，不能仅凭此参数授予历史访问权 |
| avatar_url | 展示头像的 HTTPS 地址；无效、超限或加载失败时使用默认头像 |
| context | 当前访问或咨询的 JSON 业务上下文，如商品、订单摘要、会员等级与外部业务链接 |
| attributes | 已登记的客户自定义字段；仅接收字段字典允许的键及类型，不接受任意系统字段 |
| source、campaign_id、utm_* | 来源与推广标记；按允许的字段保存，不改变身份、权限和客服容量 |
| handoff_code | 商户服务端换取的短期一次性交接码，用于传递已验证身份和较大或敏感资料 |
| locale、device_hint | 允许的语言与界面适配提示；浏览器实际能力优先，不能改变业务状态 |

租户、服务空间、页面发布版本和操作者权限由入口及认证上下文确定，公开请求不能通过 tenant_id、角色标记或任意 release_id 覆盖。重复参数、格式错误、未知受保护字段和互相冲突的值返回明确错误，不取最后一个值静默执行。链接生成器只生成当前入口已授权的组合。

兼容接入可将旧 nickName 或 nickname 映射为 display_name，avatar 映射为 avatar_url，channel 映射为 channel_code，extra_data 映射为 context。旧 uid 只有经过受信应用命名空间及签名校验后，才能映射为 external_user_id；旧 kefu_id、group_id 必须经过显式编号映射，不能直接当作新系统 UUID。旧 token 是应用接入概念，不等于新系统访客身份凭证；openid 还必须绑定具体应用和渠道，不能作为跨应用通用身份。

### 3 5 客服业务组 分配池与客户分类

客服业务组用于组织管理、接待业务范围和组内权限，例如售前组、售后组。一个客服可以加入多个获授权业务组，可配置一个主要归属组用于统计。技能是客服的能力属性，不能把技能名称、业务组和客户分类共用同一字段。

分配池是实际参与一次路由决策的候选集合，例如官网白班池、广告 A 值班池。池中保存成员、启用状态、权重、接待时段和主算法，并可以引用业务组范围。同一客服可加入多个池，但其租户内总接待容量只有一份，不因加入更多池而增加。业务组成员调整是否同步到池，必须选择动态按组取成员或维护固定成员，不能产生不可见的成员漂移。

客户分类用于商户整理客户，例如潜在客户、成交客户；客户标签可以多选，例如高意向、待回访。客户分类及标签默认不改变路由；需要参与分配时，由租户在规则中显式配置，并记录实际命中的条件。服务空间则代表品牌、项目或业务线，是会话续接范围，不能与客服业务组混同。

业务组、分配池、客户分类与标签分别提供管理页面、稳定编号和权限。删除被入口或规则引用的组、池时先显示影响范围，要求替换引用或归档；归档后不再用于新分配，已有会话及统计快照保留。

### 3 6 指定目标的组合 优先级与冲突

先校验租户、入口、身份和封禁状态，再恢复同一服务空间中应续接的会话。已有会话继续使用当前接待关系，进入新链接不会借指定客服参数自动转接。访客明确选择按新入口重新咨询时，执行幂等的结束旧会话与创建新会话操作，之后应用新入口规则。

| 目标组合 | 执行口径 |
| --- | --- |
| 都未指定 | 使用入口及服务空间的有效默认接待范围和策略 |
| 仅业务组 | 在该组及入口允许范围内，使用配置的池或组级默认策略 |
| 仅分配池 | 使用该池成员与策略，同时校验入口允许的业务范围 |
| 业务组与分配池 | 池必须与该业务组兼容，候选人取允许范围的交集 |
| 包含指定客服 | 客服必须属于最终允许范围；strict 等待该客服，prefer 不可用时执行范围内主算法 |

明确传入且被入口允许的目标，可替换对应维度的默认目标；不能顺便清除其他维度的权限限制。入口固定目标且禁止动态覆盖时，传入其他目标返回冲突。指定客服不属于选定池或业务组、池不在入口白名单、目标跨租户或已归档时，返回配置错误，不能偷偷转入全租户随机分配。

配置合法但暂时全部离线、示忙或满载，属于当前无人可接待，按等待、排队、留言或显式兜底处理。跨组与跨池兜底必须有白名单、顺序和终止条件；严格指定模式默认不跨目标兜底。建议新入口默认使用 prefer，但租户能够改为 strict，后台生成链接时显示最终口径。

历史客服优先只用于新分配的偏好，仍检查当前组、池、技能、上班、在线、示忙及容量；已经接待中的会话不因客服示忙立即重分配。人工领取、人工指派和转接遵守相同范围与容量约束。工作台提供模拟路由，显示最终候选范围、被排除原因、所用规则版本与兜底结果。

### 3 7 姓名 手机号 头像与 JSON 上下文

访客资料支持从链接、网页 SDK、商户服务端、访客表单及客服编辑进入。界面区分展示姓名、客服备注名、联系电话和已验证业务身份。手机号建议按租户默认国家或显式国际区号规范化，不把缺少验证码的录入标记为已验证；同一手机号的文字格式差异可以提示相同联系人，但不能直接合并历史。

context 必须是 JSON 对象。建议默认总大小不超过 16 KiB、嵌套不超过 5 层、对象合计最多 100 个键、单键最多 64 个字符、单个字符串最多 2000 个字符，具体上限由平台统一配置。允许字符串、数值、布尔值、空值及受限数组，超限或非法 JSON 返回字段级错误，不保存为无法展示的字符串。中文、换行、加号、百分号、井号和与号均应完整保留。

客服资料栏按键值或登记的展示结构呈现上下文，长内容可展开；HTML 作为普通文本显示，业务链接需要校验后才能打开。订单号、金额和会员等级只表示商户提供的咨询背景，不能据此授予订单查询、退款或其他业务权限。附件、头像、客户字段和当前咨询上下文使用各自的访问规则。

临时商品或订单 context 默认保存在访问及会话快照中，不自动覆盖永久客户资料。租户可以将指定键映射为已登记 attributes，配置类型、展示名称和允许更新来源。必须区分参数未提供、明确清空、数值 0 和布尔值 false，不能因真假值判断而漏写有效值。

### 3 8 GET POST 嵌入 SDK 与短期交接

GET 链接用于入口、路由提示和少量公开上下文；JSON 先序列化，再对每个参数值进行标准百分号编码，服务端只解码一次。建议链接参数总长默认限制为 2 KiB，超限提示改用 POST 或短码，不截断资料。二维码优先编码短链接，由服务端保存对应入口配置。

POST 建立访客会话接口支持结构化资料和较大 context，并返回当前访客访问凭证及初始化结果。网站嵌入 SDK 提供初始化、打开关闭、更新当前上下文、未读变化及接待状态事件。电脑和手机均使用同一身份及会话协议；跨域站点通过已配置的接入来源与受限桥接传递数据，不能直接读取父窗口位置或任意登录态。

商户后端可以用本租户集成凭证提交签名身份与资料，换取 handoff_code；建议默认 120 秒有效、一次兑换，绑定入口、应用、外部用户及重放标识。兑换成功后的刷新使用当前访客凭证；同一次兑换的合法幂等重试返回原结果，其他设备重放被拒绝。商户签名密钥不得放在网页、装修代码或二维码中。

公开手机号、昵称、uid 和 JSON 字段均按未验证资料处理。需要跨设备续接或读取已有关联客户历史时，必须完成商户服务端身份校验或平台认可的验证流程。接入文档同时提供普通链接、动态 SDK、服务端 POST 和短码示例，写明字段类型、编码、错误、覆盖规则及权限边界。

### 3 9 来源归属与资料覆盖

客户首次来源、最近访问来源和本次会话来源分别记录。首次来源创建后保持不变，最近来源随有效访问更新，会话保留创建入口及当时的渠道、路由和业务快照。重复刷新和切换链接新增访问轨迹，不改写原始咨询来源，也不自动重建会话。

资料按字段保留来源、更新时间、验证状态与修改人。建议覆盖优先级为人工锁定资料、已验证商户资料、访客明确编辑、普通链接参数；客服备注名单独保存。低可信来源不覆盖高可信或人工锁定字段。未提供字段保持原值，清空需使用明确动作并获得编辑权限。

接入来源包括当前页面、允许的上级页面、渠道及推广标记。跨来源 iframe 由宿主 SDK 明确传入允许的页面信息，无法取得来源时显示未知，不能让来源采集失败阻塞聊天。IP 由服务端依据可信代理规则取得，不能直接相信请求体中的 ip；地区只作估算展示，不作为身份依据。

保存 URL 前清理凭证、手机号、签名及未获允许的查询参数，推广参数按白名单保留。租户停用按平台政策阻断新接入和写入；单个链接停用默认只阻止由该链接新建咨询，已有授权会话的继续处理按服务空间政策执行，不能无提示丢失消息。



### 3 10 访客进入后回调

租户管理员可填写回调 URL、启停、签名密钥和允许发送的字段，独立查看测试与实际投递日志。默认关闭回调、手机号和业务上下文发送；只开放 visitor.entered 事件。接收地址使用公开 HTTPS，平台限制内网、环回、云元数据和重定向等危险目标。签名密钥只在首次生成或轮换时展示一次，关闭后不能再次读取原文。

visitor.entered 表示一次有效进入并完成初始化；conversation.created 表示新建独立咨询。重新打开链接并恢复进行中咨询仍可能产生一次进入事件，不能仅在新建会话时回调。一次页面访问生成稳定 visit_id，初始化重试沿用同值；新访问生成新值。按租户、事件类型和 visit_id 持久去重，不把手机号、昵称或公开业务编号当作身份。

回调异步入队，外部慢、超时和错误不能阻塞聊天。接收方验证签名与时间窗，并按事件编号去重；测试事件必须明确标注，不计入真实访客业务量。投递日志显示事件及访问编号、配置版本、尝试次数、HTTP 状态、脱敏错误和送达时间；可以针对原任务重试。「已入队」「对方已接收」和「最终失败」分开显示。

回调不发送平台登录态、验证码或完整访客令牌。include_phone 仅控制正式手机号字段，业务上下文还应通过字段白名单与最小化规则处理。验收覆盖恢复旧咨询仍触发进入、同 visit_id 重试不重复、签名失败、安全目标拒绝、外部超时不影响聊天和真实日志重试。

## 4 会话与客服分配

### 4 1 会话状态

| 状态 | 产品含义 | 可执行动作 |
| --- | --- | --- |
| 排队中 | 已进入人工服务队列，暂未占用客服名额 | 继续发消息、取消排队、领取或自动分配 |
| 待接单 | 已为某客服预留名额，等待其确认 | 接单、拒接、超时重分配 |
| 接待中 | 客服已正式接待 | 聊天、转接、结束 |
| 已结束 | 本次咨询关闭，保留历史和统计 | 查看历史、评价、重新发起新会话 |

自动接入模式直接从排队中进入接待中；需要确认模式经过待接单。转接属于接待关系变更，在同一个会话内记录事件。访客或客服一次网络断开不直接结束会话。留言单独记录，客服跟进时可以关联或转为新会话。

### 4 2 分配决策顺序

分配规则由资格条件、优先规则、一个主算法及兜底规则构成。租户在配置页面看到最终生效顺序，可以使用模拟分配功能检查指定访客将进入哪个接待范围。

1. 校验租户、链接、身份与访问权限，检查是否存在应续接的会话。
2. 根据链接及已验证参数确定服务空间、客服业务组、分配池和指定客服约束，判断营业时间。
3. 筛选账号有效、接待权限有效、上班、可接待、在线状态未过期且有剩余容量的客服。
4. 应用必要技能、指定客服以及配置的历史客服优先规则。
5. 使用一个主算法选出客服，并原子占用名额；资格在分配提交前再次检查。
6. 无合格客服时按链接配置排队、跨组兜底或留言；兜底范围必须显式设置。

人工调整优先级与转接也执行租户和接待权限校验。前端不能通过修改参数强制指定无权限的客服。

### 4 3 支持的策略

| 策略 | 配置与执行规则 |
| --- | --- |
| 人工领取 | 进入授权组的待接池，由客服领取；同一会话仅一人成功 |
| 轮询 | 按组内有效候选人的轮询位置分配；不合格人员跳过 |
| 最少会话 | 优先选择当前占用数量最少的客服，同量时按轮询位置与稳定标识排序 |
| 最低负载比例 | 比较当前占用与接待上限的比值，适配不同坐席容量 |
| 加权轮询 | 按客服权重安排长期分配比例，同时遵守在线与容量限制 |
| 随机 | 在合格候选人中随机选择，分配记录保留决策信息 |
| 技能匹配 | 必备技能用于过滤，可选技能用于排序，之后执行选定主算法 |
| 历史客服优先 | 历史客服仍符合当前组、技能、在线与容量要求时优先；否则回到主算法 |
| 指定客服 | 可选严格等待该客服，或优先指定客服并允许明确的组级兜底 |
| 人工指派与转接 | 授权人员指定目标客服或技能组，执行容量检查并记录原因 |

历史优先、技能和指定客服属于约束或优先级，不作为可以无限叠加的独立算法。严格指定客服与跨组兜底的冲突由配置校验提示，禁止产生无法解释的规则。

### 4 4 排队与超时

同一优先级内按入队时间先后处理；支持租户配置有限级别的客户优先级，并通过等待时长提升防止普通客户长期无法接待。界面显示排队状态，只有数据足够时才展示预计等待时间。

待接单占用容量，拒接或超时释放；同一轮重分配暂时排除拒接或超时的客服，达到重试上限后回到排队或留言。客服主动下班时停止新增分配，已有会话可以继续处理或批量转接。

自动接入模式转接到指定客服时，确认目标可接待且有容量后完成接待人切换。需要确认模式先为目标客服预留名额，原客服继续接待；目标确认后再切换正式接待人并释放原名额。拒接、超时或取消时释放目标预留，原客服继续。任意时刻只有一个正式接待人，待确认转接可以同时存在一个目标预留。转入组队列需要显式确认，成功后释放原接待名额并向访客说明等待状态。关闭会话同时释放未完成转接预留，重复任务只能释放一次容量。

降低客服上限时保留已有会话并停止新增，待占用自然回落。客服断线经过宽限期后按规则转接或告警；访客断线按单独的访客离开规则处理，不共用客服在线判定。

### 4 5 建议初始参数

以下为建议出厂配置，属于可调整产品默认值，开发评审时可修改；所有租户级时间策略按租户时区执行。

| 参数 | 建议默认 | 可配置要求 |
| --- | --- | --- |
| 自动分配主策略 | 最少会话 | 每个服务空间或链接选择一个主策略 |
| 接待方式 | 自动接入 | 可切换需要客服确认 |
| 客服接待上限 | 5 个会话 | 正整数；调低不强制结束已有会话 |
| 接单等待 | 30 秒 | 仅确认模式生效 |
| 同轮尝试上限 | 3 次 | 达到上限回队列，不无限循环 |
| 客服断线宽限 | 60 秒 | 宽限结束前停止新分配，已有会话保留 |
| 无人可接待 | 排队并显示留言入口 | 指定客服严格模式可改为等待指定客服 |
| 会话空闲自动结束 | 默认关闭 | 启用时明确按最后消息还是最后访客活动计算 |
| 旧会话可见 | 访客可见本人历史 | 可按服务空间关闭，服务端执行 |

## 5 聊天与消息交互

### 5 1 消息类型与内容展示

首版支持文字、常用表情、图片、普通文件、录音语音和系统事件。商品、订单等业务卡片采用明确的数据结构展示，只有完成真实业务接口授权后才展示订单详情；不能把访客传入的订单号视为读取订单的权限。实时语音通话、视频通话、自动语音转文字不属于首版承诺。

文字保留换行，长内容折叠后可展开；表情在各端含义一致，不支持的表情使用可理解的替代文本。系统事件用于排队、客服接入、转接、结束等状态，与人工消息、自动回复和内部备注明显区分。头像、图片和附件加载失败应显示占位及重试入口，不能留下破坏布局的空白区域。

### 5 2 输入发送与失败重试

电脑端建议默认 Enter 发送、Shift+Enter 换行，并允许客服调整；手机端建议默认回车换行、点击发送。中文输入法选词时按回车不能误发。发送前校验空白、长度、附件状态和当前会话权限；会话失效或重新分配时先提示原因并保留输入，不能发送到其他客户。

消息区区分发送中、服务器已接收、发送失败；送达和已读仅在存在对应回执时展示。服务器已接收表示消息已可靠保存，不能把本地插入气泡、网络请求发出或 WebSocket 已连接当成成功。失败气泡支持重试、复制内容和取消本地待发送项；重试沿用原消息标识，连续点击、超时重试和刷新恢复不能产生重复消息。

### 5 3 录音语音消息

录音消息是异步聊天附件，与消息提示音、语音播报和实时通话分别管理。用户主动点击录音后才请求麦克风权限，显示录音时长、结束、取消和发送操作；手机可使用按住录音与滑动取消，电脑提供点击开始及停止。建议最短 1 秒、最长 60 秒，时长属于可调整默认值，触及上限时停止录音并等待确认发送。

权限被拒绝、没有麦克风、设备占用、浏览器不支持或切到后台导致中断时，给出明确结果并保留文字入口，不自动发送不完整录音。发送前可试听与重录；接收方点击播放后显示时长、进度和暂停，一次只播放一条录音。新语音不能自行外放，播放失败支持重试；语音文件下载和保留期限遵循会话附件权限。

### 5 4 历史阅读与已读未读

消息按会话内服务端顺序展示，上翻分页保持原阅读位置。正在底部阅读时可跟随新消息；正在查看历史时不强制跳到底部，提供新消息数量与回到底部入口。图片加载、长消息展开及键盘变化不能使当前阅读位置无故跳动。

已读进度以当前可见会话中实际阅读的位置推进；后台标签页、建立连接和仅选中列表项不直接把所有消息设为已读。未读数按同一口径在列表、聊天页和其他已登录终端同步，并区分人工消息与可配置的系统提醒。旧会话可见开关只改变允许查看的历史范围，不合并新旧会话，也不改变数据保留和统计边界。

### 5 5 消息操作与撤回边界

文字支持复制，失败消息支持重发，允许引用回复并定位仍有权限查看的原消息。引用对象撤回、过期或无权限时显示对应占位，不通过引用泄露原文。建议发送者在 2 分钟内可撤回本人消息，窗口为可配置默认值；撤回由服务端判断，所有终端收到一致的撤回占位，附件同步失去对应消息访问入口。

仅本人隐藏、撤回和按保留政策清理是不同操作。隐藏不删除对方历史，不重写统计；清理遵循租户保留政策和审计权限。客服不能撤回访客消息，普通消息操作不能删除内部审计记录。关闭会话后的撤回权限、管理人员干预和附件已下载的不可追回边界，应在界面说明，不承诺撤回能够清除对方设备中的副本。

### 5 6 图片文件与本章验收

图片支持选择、粘贴截图、缩略图、放大、缩放、原图和下载；普通文件显示真实文件名、类型、大小、上传进度及下载状态。平台统一配置允许类型、大小和配额，服务端检查实际内容。上传失败可重试，重复上传可取消；尚未完成有效性检查的附件不能作为成功消息发送。

手机图片预览优先消费返回操作，关闭后仍在原会话；浏览器下载只提示已发起下载。宿主开放相册接口时，仅实际成功回调可以提示保存相册；接口不可用、权限拒绝和超时提供原图或受控下载入口，不把长期公开附件链接作为必需降级。验收覆盖中文选词、多行文本、断网重试、多端顺序、后台未读、图片预览返回、文件类型伪装、录音拒权与中断、撤回并发及附件越权。

## 6 声音提醒与正在输入

### 6 1 四类音频和通知能力

客服端分别配置消息提示音、语音播报、系统通知和录音消息。提示音播放短音效；语音播报朗读新咨询等提醒文案；系统通知由操作系统或浏览器展示；录音消息由用户主动录制并发送。关闭任一提醒不改变消息接收、未读或录音播放能力。租户可以设置默认策略，客服在授权范围内设置个人偏好，换设备时明确哪些偏好会同步。

建议默认开启普通提示音、关闭语音播报，系统通知在用户主动启用后申请权限。播报默认只读“有新的客户消息”等通用文案，不朗读客户姓名、手机号或聊天正文；启用内容播报需要单独开关，避免公共办公环境泄露资料。播报与录音播放冲突时建议优先录音，提醒可合并，不能叠加持续发声。

### 6 2 提醒事件与重复控制

可提醒事件包含新咨询、待接单、其他会话的新访客消息、转接邀请及连接异常。建议正在前台阅读当前会话时只更新界面，不弹系统通知；自己发送、历史补拉、重复回执和自动欢迎语不触发新访客提醒。同一浏览器多个工作台标签页对同一事件只提醒一次；不同设备分别遵循各自设置，不宣称所有设备天然只响一次。

提供试听、音量或静音、免打扰和提醒记录。短时间大量消息应合并，待接单和超时告警可使用不同音效，但不能无限循环。访客页面可提供独立的消息声音开关，不能由客服远程强制开启访客声音。

### 6 3 浏览器与后台运行边界

网页声音受首次用户交互、自动播放规则、标签页冻结、系统静音和省电策略影响；系统通知也依赖浏览器能力、权限及运行条件。页面提供启用提醒入口与状态检测，失败时说明原因并保留站内徽标和未读提示，不反复弹权限请求。不承诺任意浏览器关闭页面后仍可持续发声或收到通知。

通知标题和正文支持隐私显示，点击后定位到仍有权限的会话；登录过期时先重新登录，再恢复目标。后续原生客户端的推送、后台唤醒和系统托盘能力另行验收，不能用网页运行结果代替原生后台通知证据。

### 6 4 正在输入状态

建议首版支持客服与访客双向正在输入，租户可以关闭。由真实输入变化触发，不因仅获得焦点长期显示；只传递状态，不上传未发送正文。建议状态事件最多每秒一次，连续 3 秒无输入主动停止，接收方 5 秒未收到更新自动清除；上述时间是可调整默认建议。

发送完成、失焦、切换会话、转接、结束、断线和退出时清理状态。状态与当前会话及当前接待关系绑定，旧事件不得显示在其他客户会话中；多标签页使用短时合并状态，不能让一个页面停止事件覆盖另一个仍在输入的页面。正在输入不推进已读，不改变排队位置或接待容量。

### 6 5 本章验收

验收覆盖浏览器首次拒绝播放、通知拒权、关闭系统通知、免打扰、多标签页重复事件、突发消息合并及重新登录定位。正在输入需要验证中文组合输入、停顿、刷新、事件丢失、断网、转接及切换客户后自动消失；通过网络事件检查确认未发送正文未被上传。网页后台、系统锁屏与后续原生客户端分别记录实际能力，不混用验收结论。



## 7 客户资料 标签分类与访问轨迹

### 7 1 客户列表与资料页

租户端提供客户列表和详情，客服端提供授权范围内的客户资料栏。列表支持姓名或备注名、手机号、游客或已关联客户、客户分类、标签、来源渠道、接入链接、创建与最近访问时间筛选；详情串联咨询记录、访问轨迹、资料修改、标签变更和跟进备注。

客户档案包含平台客户编号、展示姓名、备注名、头像、联系方式、验证状态、业务身份绑定、分类、标签、自定义字段、首次与最近来源。可选字段按租户实际需要启用，未收集内容显示未提供；游客状态与“填写了手机号”分开，不能仅因客服录入电话就认定其已认证。

### 7 2 客户分类与标签分类

建议首版每位客户有一个主要客户分类，默认未分组；多维特征使用多选标签。租户可新增、重命名、排序、归档分类并批量调整客户归属。调整分类不更改当前客服、历史来源或会话编号。

标签由标签分类和具体标签组成，一个标签属于一个分类，客户可以拥有多个分类下的多个标签。提供分类与标签的维护、搜索、排序、合并前检查和引用计数；同一客户重复添加同一标签只保留一个关联。标签名称在同一分类内不重复，分类名称在本租户内不重复。

已被客户或规则引用的分类、标签默认归档，不删除历史。归档后不再用于新增选择，现有关联可以展示归档标记，并提供迁移到其他项的操作。规则引用归档项时提示影响，停用规则或替换条件后才能继续新分配。

### 7 3 客户自定义字段

租户维护字段编码、中文名称、类型、选项、必填范围、显示位置及编辑权限，首版支持文本、数字、日期、布尔、单选和多选。字段编码在租户内唯一；字段类型变化先检查现有值与接入映射，不能静默把旧数据转换或丢弃。

资料栏仅展示被授权的字段；接入 context 中未映射的键仍归当前业务上下文。手机号等敏感字段支持按角色隐藏、脱敏和完整查看权限，导出执行同样限制。自定义字段不能覆盖 tenant_id、身份验证状态、容量、角色和会话系统字段。

### 7 4 访问轨迹与来源统计

记录访问、打开聊天、发起咨询、首次发送、留言和评价等事件，建议包含事件编号、访客编号、访问编号、可空会话编号、入口、渠道、页面、推广标记、客户端发生时间及服务端接收时间。相同事件编号的重试不增加统计；访问、客户、咨询和消息分别计数。

客户详情按时间展示跨链接访问与会话节点，并能按入口、渠道和时间筛选；会话详情展示创建来源及本次上下文。首次来源与最近来源分别用于统计，切换链接不会篡改历史转化归属。离开与停留时长只能在能采集时记录，不把关闭页面事件缺失当成持续在线。

来源缺失、浏览器限制或匿名身份变化时明确显示未知或新访客，不通过 IP、地区或指纹强行合并客户。原始 URL、联系方式、上下文与统计聚合分别设置保留期限和查看权限，租户清理策略不得破坏仍在保留的会话记录及引用。

### 7 5 黑名单与解除

提供独立黑名单功能，默认按租户内客户身份封禁，记录目标、原因、操作者、生效时间、到期时间及解除记录。按已验证业务身份或手机号封禁属于单独规则；IP 范围封禁仅由授权管理员使用，不默认将共享网络用户整体拉黑。

封禁检查覆盖建立咨询、发送消息、上传附件及新连接授权。建议默认终止被封禁客户的进行中咨询并释放接待及预留容量，保留客户、消息和审计记录；访客看到统一不可服务提示，内部原因仅对有权限人员展示。解除或到期后允许新咨询，不自动重新打开已结束会话。

封禁、解除、删除客户是不同操作。不能以删除客户和聊天记录代替黑名单；未验证手机号、可更换浏览器或 IP 的限制需在规则说明中写明，不能承诺无法绕过的实名封禁。平台全局安全封禁与租户业务封禁分别授权和审计。

### 7 6 去重 关联与合并

相同租户、受信应用和已验证外部用户标识可以定位同一客户；相同昵称、头像、IP 或未验证电话仅提示疑似重复。不同租户客户不自动关联，不共享手机号搜索结果或聊天历史。

授权管理员可以手工合并同租户重复档案。合并前展示身份绑定、资料冲突、分类、标签、会话和附件数量，明确保留的主客户及字段选择；冲突身份未经核实不得合并。建议同一服务空间存在两条进行中会话时先处理会话冲突，再执行合并。

合并保留原客户别名、历史会话来源、操作者和变更映射，客户标签去重，不能删除旧消息后拼接成一条虚假咨询。跨设备绑定与合并均需可靠身份或管理员授权；解除绑定不能自动把已合并的历史拆散，相关恢复按审计记录处理。

### 7 7 权限 批量操作与验收

查看联系方式、修改资料、管理标签分类、批量变更、合并客户、封禁解除和导出分别授权。客服默认只操作当前接待或明确授权范围，平台人员查看正文与客户信息仍走支持授权；切换租户、客户或撤权后，已有页面和实时订阅同步失去相应权限。

批量操作先显示命中范围、数量及影响；标签默认增量添加或移除，覆盖全部标签需显式选择，客户分类替换需确认目标。小批次建议最多 200 条并保持事务一致；大批次使用持久任务，展示逐项成功失败与重试入口，重试不重复添加标签或重复封禁。

验收至少覆盖：带中文与特殊字符的 JSON 完整传递；非法参数不扩大接待范围；普通手机号不能读取历史；新链接续接保留原来源；多人重复打标无重复；批量越权不生效；封禁保留历史并阻止发送；匿名疑似重复不误合并；跨租户查询与附件全部隔离；撤权后的现有连接不能继续访问。

### 7 8 旧系统参考边界

CRMChat 源码中的客服管理分组、渠道可接范围、随机二维码候选集合和客户分组是不同机制，不宜统称为一个 group_id。其后台生成了组二维码，但当前访客初始化接口未接收 group_id；不能据此宣称已有完整按组分配。旧字段映射只是迁移适配清单，新系统按本节明确定义业务组与分配池。

旧接入资料声明 nickName、phone、avatar、openid、kefu_id、channel 与 extra_data；目前手机号优先查客户、既有资料更新路径不一致、非法 JSON 未统一拒绝。旧“拉黑”路径实际删除客户及聊天记录，站点来源统计也不能替代按客户串联的完整访问轨迹。新系统保留这些业务能力诉求，按新的身份、覆盖、封禁和事件规则实现。

## 8 客服工作台协作

### 8 1 工作台与接待状态

工作台包含待接池、本人接待、转接邀请、留言待办、会话列表、消息区和客户资料。按权限支持搜索、标签、客户分组、来源链接、时间、未读和超时筛选；列表显示最后消息摘要、未读数、接待人及真实服务状态。文字、图片、文件、语音和业务卡片使用准确摘要，不能显示无法理解的资源地址。

登录、网络连接、上班、可接待和示忙分别呈现。示忙停止新增自动分配，已有接待继续；连接异常显示重连中、重连失败或登录失效，并提供手动恢复。账号多个标签页共享接待归属与容量，仅关闭一个标签页不立即下班；登录过期不能继续表现为可接待。

### 8 2 输入草稿与上下文保持

输入草稿按租户、客服账号和会话分别保存，切换客户后恢复对应内容；退出账号或权限撤销后不能被其他账号读取。附件上传与发送对象绑定，上传过程中切换会话不能把附件发送给新选中的客户。多页编辑同一草稿时避免静默覆盖，至少保留冲突提示或各页独立草稿。

切换会话时恢复阅读位置与必要资料，未完成发送的反馈仍归属于原会话。网络恢复先校验当前接待权限再续发，不能把旧客服离线期间的草稿自动发给已经转接的客户。

### 8 3 客户资料与内部协作

客户资料包含访客身份、可信业务账号、来源轨迹、标签、备注、允许查看的历史和已授权业务上下文。访客自行填写资料与业务系统验证资料分开标识；敏感字段展示和导出按权限控制，不因公开链接携带参数就视为可信。

内部备注仅向授权成员展示，使用明显区别的输入模式与发送按钮，避免误发给访客。修改标签、资料和备注记录操作者及时间；有权限的管理者可协作查看，但协作查看不自动成为正式接待人，也不占用新的接待容量。

### 8 4 转接与接待权限变化

沿用统一分配资格与容量规则，转接前展示目标、原因及必要上下文。自动接入模式可原子切换；确认模式先预留目标容量，原客服继续接待，目标接受后再切换。拒接、超时、取消和目标下线释放预留，原接待不丢失；转入组队列需要明确提示访客重新等待。

任一时刻仅有一个正式接待人，可以同时存在一个待确认目标预留。会话关闭取消未完成转接；重复回调不得重复释放容量。转出客服和被撤销权限的成员立即失去后续发送及未授权读取能力，其他标签页同步更新；不能只隐藏按钮。

### 8 5 查询导出与验收

历史查询遵循会话边界和可见范围，支持按时间、客服、来源、状态及消息关键词筛选。导出有独立权限、范围确认、任务状态和审计，下载仍校验身份；超出套餐或保留期限时说明原因，不静默缺失数据。

验收覆盖多人抢同一待接、末位容量竞争、双页状态同步、账号切换草稿隔离、上传中切换客户、内部备注不外发、确认转接超时、关闭与转接并发、离职账号撤权及导出越权。手机工作台至少完成查看、回复、语音、转接、留言跟进和状态调整，复杂装修管理不作为手机接待的前置步骤。

## 9 欢迎语话术自动回复

### 9 1 欢迎语配置与继承

欢迎语支持文字、图片和可点击选项，多条排序、启停、适用链接与营业场景。视频欢迎语只有完成独立的上传播放及兼容验收后才开放，不能以普通图片类型替代。建议平台基础、租户、服务空间、链接采用最具体配置覆盖的继承方式，界面展示最终生效内容，不默认把所有层级全部叠加发送。

客服个人问候作为接单时的独立追加项，需要明确开关和触发条件。选项分别配置显示文案与发送内容，点击后按普通访客消息处理并执行防重复提交；欢迎语不可伪造人工接待状态或绕过严格指定客服、排队和营业规则。

### 9 2 触发时机与延迟任务

默认在新咨询建立时触发一次，而不是每次打开、刷新或恢复连接都重新发送。延迟建议统一按会话创建时间计算，配置界面明确计时基点；按排序与到达时间展示，相关值均是待评审默认建议。系统消息记录来源和规则版本，不计人工首次回复。

会话结束、触发条件失效或当前版本被撤销后，未执行任务按明确策略取消；已经发出的内容保留历史，不能被配置更新静默改写。任务重试、服务重启及多标签页不会重复发送；切换会话后迟到任务不得插入新会话。人工接入后是否继续延迟内容应提供配置，建议默认停止未发送的引导内容。

### 9 3 快捷话术库

提供客服个人库与租户公共库，支持分类、标题、内容、搜索、排序、启停和复制。公共库由租户授权成员维护，个人库仅本人及明确授权管理者可管理。建议点击话术先插入输入框，客服检查后发送；如开放一键发送，需要独立操作和清晰提示。

支持文字及已完成消息能力验证的图片、文件组合，发送前仍校验附件权限。变量仅替换当前会话中有权限的资料，缺失时提示或保留可编辑占位，不能把上一个客户的信息带入。删除话术不删除已经发送的聊天消息，公共内容更新不覆盖客服已有输入。

### 9 4 关键词规则自动回复

首版规则自动回复与后续 AI 接待分开定义，不调用大模型猜测答案。支持完全匹配、包含匹配、多个关键词、优先级、适用链接、场景与启停；建议只匹配访客新发送的文字，不匹配客服、系统消息、图片地址或历史补拉，避免回复触发回复的循环。

建议每条访客消息最多执行一条最高优先级规则，同优先级按配置排序；同一规则同会话 30 秒冷却，属于可调整默认建议。回复支持文字、图片和快捷选项，命中留痕。默认适用于排队和非营业场景，接待中是否启用单独配置，避免与人工同时重复回答；会话结束后不继续自动发送。未命中保持正常接待或留言，不虚构人工在线。

### 9 5 本章验收

验收覆盖配置继承、禁用回退、日夜切换、重复刷新、累计延迟误解、任务重试、转接与关闭、选项连点、变量缺失、个人公共库越权和关键词多规则冲突。确认欢迎语、快捷回复、规则回复与人工回复来源可区分；AI 装修只改变设计，不能自动增加 AI 接待或改变回复权限。

## 10 留言评价

### 10 1 留言入口与提交

无人接待、营业时间外、排队过久或指定客服暂不可用时，按链接策略展示留言入口，也可由访客主动选择。说明当前服务状态和预计跟进方式，不显示未经配置的响应承诺。表单支持问题描述、姓名、电话或邮箱、允许的附件；联系字段按业务配置必填，说明用途并提供隐私提示。

校验格式、长度、附件额度和提交频率；重复点击或网络重试只创建一条留言。失败保留输入与附件状态，成功返回可查询的结果。留言记录关联租户、服务空间、来源链接、访客及相关会话，但提交留言不自动制造一条已经人工接待的咨询。

### 10 2 留言处理闭环

租户按权限查看待处理、处理中、已跟进和已关闭留言，记录负责人、处理意见、跟进时间及关闭原因。允许按服务组分派和重新指派，操作留痕；留言数量、处理时长与聊天接待量分别统计。

客服可在访客再次在线时关联当前咨询，或明确创建新的跟进会话；重复操作不能创建多条会话。通过邮件、短信等渠道回复需要已配置服务与相应授权，界面展示真实发送结果；仅保存处理意见不能标记为客户已收到。客户无法联系、联系信息错误或回复失败应保留原因和后续处理入口。

### 10 3 满意度评价

会话结束后提供评价入口，建议采用五级满意度、可选标签及文字意见，评分形式属于可调整默认建议。评价仅当前会话访客可提交，默认每会话一次；是否允许期限内修改需要明确配置并保留版本。拒绝评价或关闭入口不影响查看允许的历史和再次咨询。

客服不能替客户评分，系统不能预填满意并自动提交。评价关联整个会话及实际接待记录，转接后的归属规则在统计中明确说明，不把一次评价重复计入多个咨询。管理者可以标记异常评价及处理结果，但不能直接改写客户原始评分。

### 10 4 本章验收

验收覆盖留言重复提交、离线后恢复、附件失败、必填字段、来源追踪、跨租户读取、多人指派和转会话幂等。评价覆盖未结束会话越权提交、链接转发、重复评分、过期、转接归属及管理员篡改防护。通过实际渠道回执验证对外跟进结果；真实客户收到邮件、短信或原生推送应单独记录证据，不以内部处理完成替代。

## 11 访客页面装修

### 11 1 三种装修方式

| 模式 | 租户能力 | 编辑结果 |
| --- | --- | --- |
| 基础装修 | 品牌、Logo、主色、背景、标题、欢迎语、头像、气泡、按钮和联系方式 | 可编辑的页面配置 |
| 可视化装修 | 拖拽组件、排序、分栏、间距、设备断点、显隐与自定义 CSS | 可编辑组件结构与样式 |
| 完整代码装修 | 在线编辑或上传 HTML、CSS、JavaScript 和静态资源 | 代码页面及资源版本 |

可视化组件至少包含品牌头部、公告、欢迎区、常见问题、业务卡片、消息记录、输入区、附件入口、排队提示、营业状态、联系方式和评价区。支持电脑与手机独立布局覆盖，也可以使用同一响应式布局。

基础设置与可视化编辑共享结构化设计。代码页支持源码继续编辑；任意代码自动转换成可拖拽组件不作为首版承诺。切换模式时先复制为新设计或新版本，原作品继续保留。

完整代码页可以自定义视觉与交互，通过平台提供的接口接入当前访客聊天。模板不得以视觉修改绕过身份校验、分配规则、消息保存与附件权限。自定义 JavaScript 在隔离环境中运行，预览也执行同样的隔离。

### 11 2 编辑与发布

页面支持自动保存、手动保存、撤销重做、草稿恢复、复制和版本记录。多个编辑者或多个标签页同时保存时提示版本冲突，不静默覆盖其他人的修改。

发布前提供电脑与手机预览，以及排队、在线、离线、长消息、图片和输入法键盘等状态预览。自动检查必需聊天组件或桥接能力、资源有效性、设备布局、基础可访问性和代码运行要求。校验失败显示原因并保留当前线上版本。

发布采用不可变版本，租户选择应用到哪些链接；支持发布前查看影响范围、发布记录和一键回滚。正在咨询的访客保持当前页面版本，新访问使用新发布版本；主动刷新可以加载新版本，聊天与会话不被重建。

装修异常时提供平台基础聊天页的替代入口。单纯保存、AI 生成或模板更新都不直接改变线上页面。

## 12 模板库与租户自助 AI 创作

### 12 1 模板归属

平台模板由平台管理员维护，对符合条件的租户可见。租户选择平台模板后生成本租户的设计副本，保留来源版本并允许修改。平台模板升级不覆盖租户作品；租户可以主动创建升级草稿并决定是否发布。

租户模板属于当前租户。租户通过 AI 新建时，系统立即建立一条本租户模板记录，先处于生成中或草稿状态；生成成功后进入可预览、可编辑状态。未完成的模板不出现在已发布可选列表中。租户也可以将手工装修保存为“我的模板”。

租户私有模板可以重命名、设封面、分类、复制、生成新版本、创建页面和绑定多个链接。一个模板创建多个独立页面时，各页面后续编辑互不覆盖；多个链接共用同一页面并跟随发布时，发布前明确显示所有受影响链接。

平台不得默认公开租户作品。后续如增加投稿公共模板，需要租户主动提交、授权与平台审核，属于后续扩展流程。平台下架普通模板只影响新建选择；已有页面仍运行。安全禁用发布版本是另一个带审计和兜底页面的操作。

### 12 2 AI 创建流程

1. 租户进入“我的模板”，选择 AI 创建，填写名称、用途、行业、风格和自然语言需求，可上传 Logo、素材与参考图。
2. 选择可视化模板或代码模板。默认输出可继续拖拽的结构化设计；代码模式输出可编辑的 HTML、CSS、JavaScript。
3. 系统创建本租户模板与 AI 任务，显示等待、生成、校验、成功或失败状态，用户可以离开页面稍后继续。
4. 生成成功后进入模板编辑与电脑、手机预览，允许通过对话局部修改、保留满意部分或恢复上一个版本。
5. 用户保存模板，选择创建页面或发布到指定接入链接；线上生效前再次确认发布影响范围。
6. 后续从“我的模板”重复使用，不需要开发人员复制代码或手工拼接接口。

AI 生成、重新生成和局部修改都生成可追踪的任务或版本。失败时保留输入和原草稿，显示可理解的原因；取消后迟到的结果不得覆盖用户后续修改。并发任务受到租户额度和平台限流控制。

### 12 3 AI 用量与数据

租户看到可用次数或预算、任务用量和历史。平台维护模型、计费口径、额度和降级策略；模型供应商、定价与参考图存储期限在实施前配置。AI 生成失败时区分供应商是否已产生实际费用，账目不直接按按钮点击次数累计。

装修生成使用租户主动提交的设计需求与素材，不默认提交真实聊天记录、客户资料或任何登录密钥。AI 输出走相同的预览、校验和发布流程；模型输出不能直接改变客服权限或业务规则。

### 12 4 首版内置模板

建议至少提供简洁聊天、品牌展示、售后服务、游戏服务、深色界面五类模板，每类提供电脑和手机布局。颜色优先单色或自然色系，不使用蓝紫渐变。模板应存在布局与组件差异，并覆盖长文字、空状态、排队、离线与附件展示。

## 13 SaaS 运营与统计

### 13 1 永久免费基础版与客服坐席

GoodChat 默认免费版价格 0 元、有效天数 0（长期有效）、包含 2 个客服坐席，对外主打基础客服永久免费。超出额度需要申请收费版本，未确认的付费价格和支付渠道不作虚构展示。平台可以配置各版本，已发布价格、功能和服务政策的调整必须明确展示，不无痕改写历史订阅依据。

坐席以租户中允许接待的成员计算：仅管理且未启用接待的管理员不占；启用接待的所有者、管理员和客服均占。有效且待接受的可接待邀请预占坐席。创建与接受邀请、启用接待、停用移出、撤销及到期释放须在事务内重新核对额度，不能通过并发或批量邀请超额。页面分别展示已用、预留和总上限，在线人数不是坐席数。

### 13 2 平台版本配置与官网价格

平台维护版本编码、名称、说明、整数分价格、币种、有效天数、客服坐席、功能开关、启用、公开和排序。人民币 100 分等于 1 元；0 天表示长期有效。只有启用且公开的版本进入官网定价页，官网服务端读取发布配置，后台不可用时显示真实暂不可用状态。价格、权益和开通时版本保留快照；套餐还可约束链接、存储、保留、AI 和高级装修等能力。

### 13 3 升级申请与人工开通

租户查看订阅、有效期、坐席和可申请版本，提交升级申请。申请受理、实际付款与订阅开通是不同事实，前端不能返回虚构支付成功。支付渠道未确定时采用人工核对，平台记录真实收款或审批参考；付费版本明确确认真实收款后才能开通，保留操作者和时间，重复处理幂等。平台也可按相同审计规则人工分配套餐。

原订阅到期后按当前免费版权益降级；超额限制新增坐席与相应新增业务，不删除历史聊天、客户、模板和附件。管理员仍能查看历史与升级入口；已有接待的宽限、续期及恢复规则按公开政策执行。到期、停用、降级和删除是不同动作。

### 13 4 独立聊天记录与导出

聊天记录提供独立页面，按会话编号查询，不依赖客服当前选中会话。支持客户、状态、时间、客服和来源等授权筛选；正文关键词搜索只有后端实际支持后才呈现。详情展示允许查看的文字、图片、文件、语音、引用、撤回和内部备注，不能用时间间隔猜测会话边界。

记录导出单独授权，分别处理会话元数据和消息正文，说明字段、范围、数量限制、任务进度、失效下载与审计；大批量使用异步任务。导出权限不超过在线查询权限，CSV 需防公式注入。尚未实现后端导出时不得展示假文件或「导出成功」，验收矩阵明确记录状态。

### 13 5 独立服务统计与时间口径

服务统计独立显示真实访客、新客户、咨询、排队、接待、结束、公开消息、平均等待及平均人工首响，提供按客服、来源和日期汇总。无记录与请求失败分开，不填虚构增长率、模拟曲线或失败时的假零值。

默认时区 Asia/Shanghai。自然日期的结束日包含全天，内部使用带时区半开区间；访客按周期去重，访问次数单列，会话按创建时间、消息按发送时间、客服按实际接待记录归属。转接不增加唯一咨询总量，多人参与与结束归属须说明；系统欢迎语不计人工首响。页面、接口和导出采用相同权限与口径，通过可复算数据核验跨日和转接边界。
