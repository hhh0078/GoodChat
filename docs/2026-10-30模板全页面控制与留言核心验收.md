# 模板全页面控制与留言核心验收

## 页面与核心能力

- 已绑定模板的会话移除宿主品牌头栏和通用附件栏；最底部技术支持仍由可信宿主显示。未绑定模板继续使用原生访客页面。
- 顶部品牌、留言按钮、输入与附件外观由静态模板的 HTML/CSS 控制。官方 SDK/UI 保持冻结，AI 只修改普通页面文件。
- SDK `1.0.2` 提供零参数 `GoodChat.openLeaveMessage()`、`GoodChat.openEvaluation()`；声明式按钮分别使用 `data-gc-action="leave-message"`、`evaluation`。
- SDK 经白名单桥打开当前访客的官方表单，不接受身份、会话编号、正文或提交参数。提交仍使用父层访客凭证与既有服务端校验。评价入口由固定聊天脚本按已结束状态显示。
- 预览使用本地说明弹框。平台候选脚本检查新增方法、弹框关闭及声明式留言按钮，不发送真实留言。
- 跨表单调用须先关闭或完成现有表单，重复调用不会清空草稿。上传或提交进行中也不能切换表单。

## 首屏与输入恢复

开发版完整错误确认：浏览器扩展在 body 首位注入零尺寸 `__PHOENIX_THEMED_EMPTY_SYMBOL_DEFS_ID__` SVG 定义容器，抢占 Next Metadata 隐藏节点的位置，触发 React #418。

`beforeInteractive` 只识别此精确 ID、零尺寸和 SVG definitions 签名，将完整节点移到 body 尾部；首次水合后停止短期观察。保留扩展节点与 SVG ID，不添加全局 `suppressHydrationWarning`，不放宽浏览器权限策略。扩展自身的 `unload` 提示不属于业务 SDK。

模板在布局提交后挂载。新文档通过新随机值重新握手，旧端口的接收和异步返回都被拒绝；load 事件不再误关闭已经建立的新通道。首个可见且从未连通的空白文档只自动恢复一次，已连通页面不自动重建。
